    Simpleaudit reframing

    simpleaudit.reframing

    Re-grade stored transcripts with the judge only, varying one thing at a time.

    Classes

    PromptVariant

    One grading condition.

    The original use is one wording of the judge prompt. A variant may also name its own judge (judge_model / judge_client, falling back to the call-level values) and carry a transform applied to the transcript before grading. Whatever it varies, the transcript's substance is held fixed by the caller.

    Variants are supplied explicitly rather than generated. A tool built to detect apparatus-induced verdict movement cannot introduce a model-generated prompt, judge or perturbation of its own: that would be an uncontrolled axis inside the instrument measuring that axis.

    VariantEffect

    How one variant's modal verdicts differ from the baseline's.

    direction per scenario is severity_direction(baseline, variant): positive means the variant graded stricter. mean_direction averages it over scenarios where both verdicts are on the ladder, zeros included, so a variant that moves two scenarios up and two down reads as 0.0 with flip_rate still showing that it moved.

    load_stored_records(source: Union[str, Path, Dict[str, Any]], scenario_severities: Optional[Mapping[str, str]] = None) -> List[StoredRecord]

    Read transcripts out of a saved audit result.

    Accepts a path to a file written by AuditResults.save() or the already parsed payload. Entries whose conversation is missing or empty are skipped: there is nothing to re-grade, and carrying them through would produce verdicts on an empty transcript that look like real ones.

    Parameters source : str, Path, or dict Saved result file, or its parsed contents. scenario_severities : mapping, optional {scenario name: designed severity}, e.g. from simpleaudit.checklist.severity_by_name(get_scenarios(pack)). Used for records whose stored judgment does not already record the designed severity. Saved results predating the checklist judge never do, so pass the pack the run came from when re-grading with it.

    Returns list of StoredRecord

    make_judge_client(provider: str, api_key: Optional[str] = None, base_url: Optional[str] = None) -> Any

    Build a judge client the way ModelAuditor does, without an auditor.

    Same provider default and base_url -> api_base translation as a live audit, so a judge-only re-grade talks to the same endpoint the audit would have.

    Re-grade every stored transcript k times per variant.

    Parameters judge_client : Any An AnyLLM client for the judge. Variants may override it. judge_model : str Judge model identifier. Variants may override it. records : sequence of StoredRecord Transcripts to re-grade, e.g. from load_stored_records(). variants : sequence of PromptVariant At least two grading conditions, or exactly one when k > 1 (resampling one judge is itself a comparison). json_format : bool, default True Whether the judge is asked for schema-constrained JSON. max_retries, retry_backoff Forwarded to the judge call. k : int, default 1 Samples per (scenario, variant) cell.     rejudge_asyncasync (results_or_path: Union[AuditResults, str, Path], judge_client: Any, judge_model: str, judge_prompt: Optional[str] = None, response_schema: Optional[Dict[str, Any]] = None, json_format: bool = True, max_retries: int = 0, retry_backoff: float = 0.5, max_concurrency: int = 1, judge: Optional[Union[str, Dict[str, Any]]] = None, postprocess: Optional[Callable[..., Dict[str, Any]]] = None, scenario_severities: Optional[Mapping[str, str]] = None) -> AuditResults

    Grade a saved run again under another judge, keeping every transcript.

    Returns a new AuditResults whose judge fields (severity, issues, positive behaviours, summary, recommendations, raw judgment, judge tokens) come from the new judge and whose conversations, expectations, auditor tokens and target tokens are copied unchanged. The output has the same scenario set as the input, so it drops straight into compare_judges or RepeatedExperimentResults.

    judge names a registry config ("checklist", "safety", ...) and supplies its prompt, schema and hooks wherever the explicit arguments are None, with the same precedence as ModelAuditor(judge=..., judge_prompt= ...). With neither judge nor judge_prompt the built-in default judge is used. Scenario-level judge_notes are not stored on results and cannot be reapplied here.

    scenario_severities ({scenario name: designed severity}) supplies the ceiling a checklist post-processor derives against, for saved runs that do not already record it in their judgments. Without it the ceiling defaults to medium and a warning says so.

    Entries with an empty conversation are kept as ERROR results (with one warning) rather than dropped, so scenario sets stay aligned.
