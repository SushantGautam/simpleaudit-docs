    simpleaudit.scenarios.healthbench_loader

    Load OpenAI's HealthBench as SimpleAudit scenarios at run time.

    Load OpenAI's HealthBench as SimpleAudit scenarios at run time.

    HealthBench (Arora et al., 2025, arXiv:2505.08775) and HealthBench Professional (Soskin Hicks et al., 2026, arXiv:2604.27470) are MIT-licensed benchmarks of health conversations graded with physician-written rubrics. OpenAI asks that examples from both are not posted online in plain text, to keep them out of training corpora. This module therefore ships no HealthBench text. It downloads the data from OpenAI into a local cache, checks the file's SHA-256 against the version pinned below, and converts examples into v2 scenarios in memory.

    from simpleaudit import ModelAuditor, load_healthbench_scenarios

auditor = ModelAuditor(..., judge="checklist")
scenarios = load_healthbench_scenarios("hard", themes=["emergency_referrals"], limit=20)
results = auditor.run(scenarios, max_turns=1)

    Use the checklist judge. It must quote the reply for every criterion it marks as violated, and the quote is checked against the transcript. That matters here because some criteria describe a different reply ("references a YouTube source ..."). In a test run (2026-10-02, gpt-4o judging gpt-4o-mini) the default judge reported such criteria as faults of replies that did not contain them, also with a judge note telling it not to; the checklist judge marked them met.

    Subsets: "main" (5,000 examples), "hard" (1,000), "consensus" (3,671, rubrics hold only the shared consensus criteria) and "professional" (525 clinician chats).

    How an example becomes a scenario:

    • test_prompt: the single user message.
    • expected_behavior: the rubric criteria verbatim, most heavily weighted first. Criteria worth positive points are prefixed "Should:", criteria worth negative points "Should NOT:".
    • description: what the HealthBench theme tests, plus the physicians' category for the example when the data has one (for instance "emergent").
    • category, subcategory and severity: from the theme, see THEMES and _severity.
    • source and metadata: origin, URL, licence, prompt id, rubric points and the HealthBench canary string.

    What does not carry over:

    • Multi-turn examples are skipped (42% of the main set, 22% of Professional). SimpleAudit sends test_prompt as the first message and has no field for earlier turns; pasting them into one message would show the target earlier "assistant" answers as text the user wrote.
    • Rubric weights. HealthBench scores a response from the points of the criteria it meets; SimpleAudit's judge returns a severity verdict. The points are kept in metadata.healthbench.points.
    • Follow-up turns. A rubric grades one reply. With max_turns > 1 the probe model adds follow-ups the rubric was not written for, so use max_turns=1 when you want HealthBench-style grading.

    Audit results and HTML exports contain the test prompts. Don't publish them for runs on these scenarios, or remove the prompts first.

    Licence of the data (not of this module): HealthBench is released under the MIT licence of openai/simple-evals, "Copyright (c) 2024 OpenAI". HealthBench Professional ships its own MIT licence, "Copyright (c) 2026 OpenAI".

    def load_healthbench_scenarios(
    subset: str = "main",
    *,
    themes: Optional[Iterable[str]] = None,
    min_criteria: Optional[int] = None,
    max_criteria: Optional[int] = None,
    limit: Optional[int] = None,
    seed: int = 0,
    path: Optional[str] = None,
    cache_dir: Optional[str] = None,
) -> List[Dict]:
    """
    Build v2 scenarios from a HealthBench subset.

    Args:
        subset: "main", "hard", "consensus" or "professional".
        themes: keep only these themes, e.g. ["emergency_referrals", "hedging"]. For
            "professional" the themes are the use cases "consult", "writing", "research".
        min_criteria, max_criteria: keep only examples whose rubric has this many
            criteria. The scenario guideline asks for 3-7 expected behaviours; HealthBench
            rubrics have 2-48 (Professional 1-5), so the default keeps them all.
        limit: return a random sample of at most this many scenarios (after filtering).
        seed: seed for that sample, so the same call returns the same scenarios.
        path: read a local copy (JSONL, or the Professional zip) instead of downloading.
        cache_dir: where downloads are kept (default ~/.cache/simpleaudit/healthbench).

    Returns:
        Scenario dicts in file order. Multi-turn examples are always skipped.
    """
    if subset not in SUBSETS:
        raise ValueError(f"Unknown HealthBench subset {subset!r}. Available: {', '.join(SUBSETS)}")
    data = Path(path).read_bytes() if path else _fetch(subset, cache_dir)
    wanted = set(themes) if themes is not None else None

    examples = []
    for row in _read_rows(data):
        example = _normalise(row, subset)
        n = len(example["criteria"])
        if len(example["messages"]) != 1 or example["messages"][0].get("role") != "user":
            continue
        if wanted is not None and example["theme"] not in wanted:
            continue
        if (min_criteria is not None and n < min_criteria) or (max_criteria is not None and n > max_criteria):
            continue
        if not any(points > 0 for _, points in example["criteria"]):
            continue  # HealthBench cannot score an example without positive points
        examples.append(example)

    if limit is not None and limit < len(examples):
        keep = set(random.Random(seed).sample(range(len(examples)), limit))
        examples = [ex for i, ex in enumerate(examples) if i in keep]
    return [_to_scenario(ex, subset) for ex in examples]
