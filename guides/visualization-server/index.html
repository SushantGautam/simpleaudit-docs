    Visualization server

    Visualization Server¶

    The Visualization Server module provides a local FastAPI web interface for exploring SimpleAudit results. It serves an interactive HTML visualizer, exposes REST endpoints for file discovery and data retrieval, and supports optional secret-based authentication. The server reads JSON result files from a configured directory, validates their structure, and renders them in the browser.

    Configuration¶

    The server relies on two environment variables for configuration:

    Variable Description Default
    SIMPLEAUDIT_VISUALIZER_SECRET Secret string required in the X-Secret header for API access. If empty, authentication is disabled. ""
    SIMPLEAUDIT_VISUALIZER_EMAIL Contact email displayed in the frontend when authentication is enabled. "sushant@simula.no"

    The results directory is set programmatically via the RESULTS_DIR global variable. Ensure this variable points to a valid directory containing audit result JSON files before starting the server.

    Authentication¶

    If SIMPLEAUDIT_VISUALIZER_SECRET is set, all API endpoints (except /api/auth) require a valid X-Secret header. The server uses constant-time comparison (secrets.compare_digest) to prevent timing attacks.

    To test authentication:

    curl -H "X-Secret: your-secret-here" http://localhost:8000/api/auth

    Response when auth is enabled and valid:

    {
  "ok": true,
  "enabled": true,
  "contact_email": "sushant@simula.no"
}

    API Endpoints¶

    GET /¶

    Serves the main visualization page (visualizer.html).

    GET /scenario_viewer.html¶

    Serves the standalone scenario viewer page.

    GET /favicon.png¶

    Serves the favicon (thumbnail.png).

    GET /api/auth¶

    Verifies the provided secret and returns authentication status.

    Parameters: - X-Secret (Header, optional): The secret string. Required if SIMPLEAUDIT_VISUALIZER_SECRET is set.

    Response: - ok (bool): true if the request is authorized. - enabled (bool): true if a secret is configured. - contact_email (str): The configured contact email.

    GET /api/files¶

    Returns the file tree structure of JSON files in the results directory.

    Response: 

    {
  "tree": [
    {
      "name": "folder_name",
      "type": "folder",
      "path": "folder_name",
      "children": [
        {
          "name": "results.json",
          "type": "file",
          "path": "folder_name/results.json"
        },
        {
          "name": "experiment.json",
          "type": "experiment",
          "path": "folder_name/experiment.json",
          "models": ["model_a", "model_b"]
        }
      ]
    }
  ]
}

    Types: - file: Single audit result file. - experiment: Multi-model experiment file. Includes a models list. - folder: Directory containing valid JSON files.

    GET /api/json/{file_path}¶

    Retrieves the contents of a specific JSON file.

    Parameters: - file_path (Path): Relative path from the results directory.

    Security: - Prevents directory traversal attacks by resolving real paths and ensuring they start with the results directory root. - Only serves .json files.

    Response: - JSON content of the file.

    Data Validation¶

    The server validates JSON files to ensure they contain valid audit results. A file is considered valid if it matches one of the following structures:

    1. Legacy Shape: A list of audit result objects. 

      [
  {
    "scenario_name": "test",
    "severity": "high"
  }
]

    2. Current Shape: An object with a results list. 

      {
  "results": [
    {
      "scenario_name": "test",
      "severity": "high"
    }
  ]
}

    3. Experiment Shape: An object with a runs dictionary. 

      {
  "runs": {
    "model_a": [
      {
        "results": [
          {
            "scenario_name": "test",
            "severity": "high"
          }
        ]
      }
    ]
  }
}

    An audit result object must contain either scenario_name or name, and a severity field.

    Standalone HTML Export¶

    The export_standalone_html function creates a self-contained HTML file with audit results inlined. This file can be opened directly in a browser without a server.

    Function Signature: 

    def export_standalone_html(json_path: str, output_path: str) -> str

    Parameters: - json_path: Path to the audit results JSON file. - output_path: Where to write the standalone HTML file.

    Returns: - The output path.

    Raises: - ValueError: If the JSON is not valid audit data or the template is missing.

    Example Usage: 

    from visualization.server import export_standalone_html

export_standalone_html("results/audit.json", "output/standalone.html")

    Running the Server¶

    Start the server using uvicorn:

    uvicorn visualization.server:app --host 0.0.0.0 --port 8000

    Ensure RESULTS_DIR is set before starting the server. For example:

    import os
from visualization.server import app, RESULTS_DIR

# Set the results directory
RESULTS_DIR = os.path.abspath("path/to/results")

# Start the server
import uvicorn
uvicorn.run(app, host="0.0.0.0", port=8000)

    Notes¶

    • The server uses synchronous endpoints for file operations to avoid blocking the event loop. FastAPI runs these in a thread pool.
    • File tree generation parses all JSON files in the results directory. For large directories, this may take time.
    • The visualizer detects inlined data in standalone HTML files and renders it as a custom upload.
