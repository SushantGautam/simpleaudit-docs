    Cli usage

    CLI Usage¶

    SimpleAudit provides command-line interface (CLI) tools audit, scan, report. CLI wraps core Python API. Enables quick audits, batch processing, integration CI/CD pipelines.

    Installation¶

    Install via pip:

    pip install simpleaudit

    Verify installation:

    simpleaudit --version

    Global Options¶

    All commands accept global flags.

    Flag Description
    -v, --verbose Enable debug logging.
    -q, --quiet Suppress non-error output.
    --config <path> Load custom configuration file (YAML/JSON).
    --version Display version number.
    --help Show help message.

    Core Commands¶

    1. audit¶

    Run security audit on target directory or file.

    Syntax:

    simpleaudit audit [OPTIONS] <target>

    Parameters:

    • <target>: Path to file or directory.
    • --rules <list>: Comma-separated list of rule IDs to apply. Default: all enabled rules.
    • --ignore <path>: Path to ignore file (similar to .gitignore).
    • --format <fmt>: Output format. Options: text, json, sarif, html. Default: text.
    • --output <path>: Write results to file. Default: stdout.
    • --severity <level>: Minimum severity to report. Options: low, medium, high, critical.

    Examples:

    Audit current directory, output JSON:

    simpleaudit audit . --format json --output results.json

    Audit specific file, high severity only:

    simpleaudit audit app.py --severity high

    Use custom ignore file:

    simpleaudit audit src/ --ignore .auditignore

    2. scan¶

    Fast, shallow scan for obvious vulnerabilities. Less thorough than audit.

    Syntax:

    simpleaudit scan [OPTIONS] <target>

    Parameters:

    • <target>: Path to file or directory.
    • --quick: Enable quick mode (skip deep analysis).
    • --parallel <n>: Number of parallel workers. Default: CPU count.

    Examples:

    Quick scan with 4 workers:

    simpleaudit scan ./project --quick --parallel 4

    3. report¶

    Generate human-readable report from previous audit results.

    Syntax:

    simpleaudit report [OPTIONS] <input_file>

    Parameters:

    • <input_file>: Path to JSON audit result file.
    • --template <path>: Custom Jinja2 template path.
    • --format <fmt>: Output format. Options: html, pdf, markdown. Default: html.
    • --output <path>: Output file path.

    Examples:

    Generate HTML report:

    simpleaudit report results.json --format html --output report.html

    Generate Markdown summary:

    simpleaudit report results.json --format markdown

    4. config¶

    Manage configuration settings.

    Subcommands:

    • init: Create default config file.
    • show: Display current effective configuration.
    • set: Set specific config value.

    Examples:

    Initialize config:

    simpleaudit config init --output config.yaml

    Show current config:

    simpleaudit config show

    Set rule threshold:

    simpleaudit config set rules.max_severity high

    Configuration File¶

    SimpleAudit reads simpleaudit.yaml from project root or path specified via --config.

    Example simpleaudit.yaml:

    rules:
  enabled:
    - sql_injection
    - xss
    - hardcoded_secrets
  disabled:
    - deprecated_api

severity:
  min_report: medium

output:
  format: json
  include_context: true

scanner:
  max_file_size_mb: 10
  ignore_patterns:
    - "*.min.js"
    - "node_modules/"
    - ".git/"

    Exit Codes¶

    CLI returns specific exit codes for scripting.

    Code Meaning
    0 Success. No issues found or below threshold.
    1 Issues found.
    2 Critical issues found.
    3 Error occurred (invalid args, missing file).
    4 Configuration error.

    Example Script Usage:

    simpleaudit audit . --severity high
if [ $? -eq 1 ]; then
  echo "Audit failed: High severity issues detected."
  exit 1
fi

    Environment Variables¶

    CLI respects environment variables for configuration overrides.

    Variable Description
    SIMPLEAUDIT_CONFIG Path to config file.
    SIMPLEAUDIT_LOG_LEVEL Logging level (DEBUG, INFO, WARNING, ERROR).
    SIMPLEAUDIT_CACHE_DIR Directory for caching scan results.

    Example:

    export SIMPLEAUDIT_LOG_LEVEL=DEBUG
simpleaudit audit .

    Best Practices¶

    1. Use in CI/CD: Add simpleaudit audit . --format sarif to build pipeline. Fail build on exit code 1 or 2.
    2. Ignore Generated Files: Always use --ignore or config ignore_patterns to skip node_modules, vendor, build artifacts.
    3. Baseline Scanning: Run audit before major refactors. Save JSON output. Compare future runs to detect regressions.
    4. Custom Rules: Use --rules flag to focus on specific vulnerabilities during development.

    Troubleshooting¶

    • Permission Denied: Ensure user has read access to target directory.
    • Timeout: Large projects may take time. Increase --parallel workers or use --quick for initial checks.
    • No Output: Check --severity filter. Issues may exist but below threshold. Lower severity to low to verify.
    • Config Errors: Run simpleaudit config show to validate current settings. Check YAML syntax.

    API Reference¶

    For programmatic usage, see simpleaudit.cli module.

    • main(): Entry point.
    • parse_args(): Argument parser.
    • run_audit(): Core audit logic.
    • generate_report(): Report generation logic.

    CLI designed for simplicity. Complex workflows use Python API directly.
