Cli usage

CLI Usage

The simpleaudit library provides a robust command-line interface (CLI) that allows developers and security researchers to execute audit workflows without writing custom Python scripts. The CLI serves as the primary entry point for interacting with the audit engine, enabling users to specify targets, configure scanning parameters, and manage output formats directly from the terminal.

This page documents the command-line options, flags, and common workflows for running audits using the simpleaudit executable.

Overview

The CLI is built using the argparse standard library module, ensuring compatibility across Python versions and operating systems. The main entry point is typically invoked via the simpleaudit command after installation.

The core workflow involves: 1. Target Definition: Specifying the URL, IP address, or file path to audit. 2. Configuration: Setting scan depth, timeout limits, and specific audit modules. 3. Execution: Running the audit engine. 4. Reporting: Generating reports in various formats (JSON, HTML, CSV).

Basic Syntax

The general syntax for running an audit is:

simpleaudit [options] <target>

Where <target> is the resource to be audited (e.g., https://example.com, 192.168.1.1, or /path/to/local/file).

Command-Line Options

The following table details the available command-line flags and their descriptions.

Flag Description Default
-h, --help Show the help message and exit. -
-v, --verbose Enable verbose logging output. False
-q, --quiet Suppress all output except critical errors. False
-t, --timeout Set the request timeout in seconds. 30
-d, --depth Set the maximum crawl depth for web targets. 1
-o, --output Specify the output file path for the report. stdout
-f, --format Specify the report format (json, html, csv). json
-u, --user-agent Custom User-Agent string for HTTP requests. simpleaudit/1.0
--no-ssl-verify Disable SSL certificate verification. False
--proxy Set the proxy URL for outbound requests. None
--modules Comma-separated list of specific audit modules to run. all
--exclude Comma-separated list of modules to exclude. None

Common Workflows

1. Basic Audit

To perform a standard audit on a web target with default settings:

simpleaudit https://example.com

This command will execute all enabled audit modules against the target and output the results to stdout in JSON format.

2. Verbose Debugging

When troubleshooting connection issues or understanding the audit process, use the --verbose flag:

simpleaudit -v https://example.com

This will print detailed logs to stderr, including request/response headers, module execution status, and any exceptions encountered.

3. Saving Reports to File

To save the audit results to a specific file in HTML format:

simpleaudit -f html -o report.html https://example.com
  • -f html: Specifies the output format as HTML.
  • -o report.html: Directs the output to a file named report.html.

4. Custom Timeout and Depth

For large websites or slow networks, you may need to adjust the timeout and crawl depth:

simpleaudit -t 60 -d 3 https://example.com
  • -t 60: Sets the timeout to 60 seconds.
  • -d 3: Allows the crawler to go up to 3 levels deep into the site structure.

5. Running Specific Modules

If you only want to run specific audit modules (e.g., ssl_check and header_check), use the --modules flag:

simpleaudit --modules ssl_check,header_check https://example.com

This reduces execution time and focuses the report on specific areas of interest.

6. Using a Proxy

To route traffic through a proxy server:

simpleaudit --proxy http://proxy.example.com:8080 https://example.com

7. Disabling SSL Verification

For testing internal or self-signed SSL certificates:

simpleaudit --no-ssl-verify https://internal.example.com

Warning: Disabling SSL verification is insecure and should only be used in controlled testing environments.

Output Formats

The CLI supports three primary output formats, selectable via the -f or --format flag.

JSON (Default)

The default format is JSON, which is ideal for programmatic processing and integration with other tools.

{
  "target": "https://example.com",
  "timestamp": "2023-10-27T12:00:00Z",
  "results": [
    {
      "module": "ssl_check",
      "status": "pass",
      "details": "SSL certificate is valid."
    },
    {
      "module": "header_check",
      "status": "fail",
      "details": "Missing X-Content-Type-Options header."
    }
  ]
}

HTML

The HTML format generates a human-readable report suitable for sharing with non-technical stakeholders.

simpleaudit -f html -o audit_report.html https://example.com

CSV

The CSV format is useful for importing results into spreadsheets or database systems.

simpleaudit -f csv -o results.csv https://example.com

Exit Codes

The CLI returns specific exit codes to indicate the outcome of the audit, which is useful for scripting and CI/CD pipelines.

Code Description
0 Audit completed successfully with no critical issues found.
1 Audit completed, but critical issues were detected.
2 Audit failed due to an error (e.g., target unreachable, invalid arguments).

Example usage in a shell script:

simpleaudit https://example.com
if [ $? -eq 1 ]; then
    echo "Audit failed: Critical issues found."
    exit 1
fi

Configuration File Support

While the CLI primarily uses command-line arguments, it also supports a configuration file for persistent settings. If a simpleaudit.conf file is present in the current working directory or the user's home directory, it will be loaded first. Command-line arguments override configuration file settings.

Example simpleaudit.conf:

[general]
timeout = 30
depth = 1
user_agent = simpleaudit/1.0

[output]
format = json

Troubleshooting

  • Permission Denied: Ensure you have read permissions for local file targets or network access for remote targets.
  • Timeout Errors: Increase the timeout value using -t for slow targets.
  • SSL Errors: If you encounter SSL errors with self-signed certificates, use --no-ssl-verify for testing purposes.
  • Module Not Found: Ensure the specified module name in --modules is valid. Use simpleaudit --help to view available modules if listed.

Best Practices

  1. Use Verbose Mode for Debugging: Always use -v when first running an audit on a new target to understand what is happening.
  2. Save Reports: Use -o to save reports for historical tracking and compliance.
  3. Limit Depth: For large websites, limit the crawl depth (-d) to avoid excessive resource consumption.
  4. Custom User-Agent: Set a descriptive User-Agent (-u) to identify your audit tool to web servers.

By leveraging these CLI options, you can efficiently integrate simpleaudit into your development workflow, CI/CD pipelines, and manual security assessments.
