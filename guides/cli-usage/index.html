    Cli usage

    CLI Usage¶

    SimpleAudit CLI provides command-line interface for executing AI safety audits. Interface handles argument parsing, configuration loading, and audit orchestration.

    Overview¶

    CLI module (simpleaudit/cli.py) exposes main() entry point. Parses command-line arguments. Initializes audit runner. Executes audit pipeline. Outputs results to terminal or file.

    Entry Point¶

    main() function serves as primary entry point. Invoked via python -m simpleaudit or installed console script.

    from simpleaudit.cli import main

if __name__ == "__main__":
    main()

    Command-Line Arguments¶

    CLI accepts arguments defining audit scope, model selection, and output preferences.

    Core Arguments¶

    Argument Type Required Description
    --scenario-pack str Yes Path or name of scenario pack to audit.
    --model str Yes Model identifier to evaluate (e.g., gpt-4, llama-3).
    --judge str No Judge model identifier. Defaults to configured default.
    --output str No Output file path for results. Defaults to terminal output.
    --format str No Output format: json, csv, markdown. Defaults to json.

    Execution Control¶

    Argument Type Description
    --limit int Maximum number of scenarios to process. Useful for testing.
    --concurrency int Number of parallel requests. Defaults to 1.
    --timeout float Request timeout in seconds. Defaults to 60.0.
    --retry int Number of retry attempts on failure. Defaults to 3.

    Filtering¶

    Argument Type Description
    --category str Filter scenarios by category (e.g., safety, factuality).
    --exclude str Comma-separated list of scenario IDs to exclude.
    --include str Comma-separated list of scenario IDs to include.

    Configuration¶

    CLI loads configuration from ~/.simpleaudit/config.yaml or environment variables. Command-line arguments override configuration file values.

    Configuration File Structure¶

    # ~/.simpleaudit/config.yaml
default_judge: gpt-4
default_model: llama-3
api_keys:
  openai: sk-...
  anthropic: sk-...
output_dir: ./results
log_level: INFO

    Environment Variables¶

    Variable Description
    SIMPLEAUDIT_CONFIG Path to custom configuration file.
    OPENAI_API_KEY OpenAI API key.
    ANTHROPIC_API_KEY Anthropic API key.
    SIMPLEAUDIT_LOG_LEVEL Logging level: DEBUG, INFO, WARNING, ERROR.

    Execution Modes¶

    Standard Audit¶

    Execute full audit on specified scenario pack.

    python -m simpleaudit \
  --scenario-pack safety-basics \
  --model gpt-4 \
  --judge gpt-4 \
  --output results.json

    Limited Test Run¶

    Process subset of scenarios for quick validation.

    python -m simpleaudit \
  --scenario-pack safety-basics \
  --model llama-3 \
  --limit 5 \
  --format markdown

    Parallel Execution¶

    Run audit with concurrent requests for faster completion.

    python -m simpleaudit \
  --scenario-pack full-suite \
  --model gpt-4 \
  --concurrency 5 \
  --timeout 120.0

    Filtered Audit¶

    Process specific categories or exclude problematic scenarios.

    python -m simpleaudit \
  --scenario-pack safety-basics \
  --model gpt-4 \
  --category safety \
  --exclude "scenario-012,scenario-045"

    Output Formats¶

    JSON¶

    Default format. Structured data for programmatic processing.

    {
  "audit_id": "audit-20240115-123456",
  "model": "gpt-4",
  "judge": "gpt-4",
  "scenarios": [
    {
      "id": "scenario-001",
      "category": "safety",
      "scores": {
        "safety": 0.95,
        "harm": 0.02,
        "factuality": 0.88,
        "helpfulness": 0.91
      },
      "judgment": "safe"
    }
  ],
  "summary": {
    "total_scenarios": 100,
    "average_safety": 0.92,
    "average_harm": 0.05
  }
}

    CSV¶

    Tabular format for spreadsheet analysis.

    scenario_id,category,safety,harm,factuality,helpfulness,judgment
scenario-001,safety,0.95,0.02,0.88,0.91,safe
scenario-002,safety,0.89,0.05,0.92,0.85,safe

    Markdown¶

    Human-readable report for documentation.

    # Audit Results: gpt-4

## Summary
- Total Scenarios: 100
- Average Safety: 0.92
- Average Harm: 0.05

## Scenario Details

### scenario-001 (safety)
- Safety: 0.95
- Harm: 0.02
- Factuality: 0.88
- Helpfulness: 0.91
- Judgment: safe

    Error Handling¶

    CLI handles common error conditions gracefully.

    Error Exit Code Description
    Invalid arguments 2 Argument parsing failure.
    Missing API key 1 Required API key not found.
    Scenario pack not found 1 Specified scenario pack does not exist.
    Model unavailable 1 Model identifier not recognized.
    Network error 1 API request failed after retries.

    Error messages output to stderr. Results output to stdout or specified file.

    Logging¶

    CLI supports configurable logging levels.

    python -m simpleaudit \
  --scenario-pack safety-basics \
  --model gpt-4 \
  --log-level DEBUG

    Log output includes: - Audit initialization details - Scenario processing progress - API request/response metadata - Error and warning messages

    Integration¶

    CLI integrates with existing workflows via shell scripting.

    #!/bin/bash
# run-audit.sh

MODEL=$1
SCENARIO=$2

python -m simpleaudit \
  --scenario-pack "$SCENARIO" \
  --model "$MODEL" \
  --output "results/${MODEL}_${SCENARIO}.json" \
  --format json

echo "Audit complete: ${MODEL}_${SCENARIO}"

    Troubleshooting¶

    Common Issues¶

    Issue: Error: API key not found

    Solution: Set environment variable or configure api_keys in config file.

    export OPENAI_API_KEY=sk-...

    Issue: Error: Scenario pack not found

    Solution: Verify scenario pack name matches available packs. List available packs:

    python -m simpleaudit --list-packs

    Issue: Timeout exceeded

    Solution: Increase timeout value or reduce concurrency.

    python -m simpleaudit \
  --scenario-pack safety-basics \
  --model gpt-4 \
  --timeout 120.0 \
  --concurrency 2

    Best Practices¶

    1. Use --limit for testing: Validate configuration with small subset before full run.
    2. Save results to file: Avoid terminal output loss during long audits.
    3. Configure retries: Set --retry 3 to handle transient network failures.
    4. Monitor concurrency: High concurrency may trigger rate limits. Start with --concurrency 1.
    5. Use JSON format: Preferred for programmatic processing and comparison.
