Advanced judging strategies

Advanced Judging Strategies

The simpleaudit library provides specialized judge configurations to handle complex evaluation scenarios where standard scoring may be insufficient. This page details two advanced strategies: Cross-Judging (using multiple judge types for robust scoring) and Abstention Logic (specifically designed to evaluate when a model should refuse to answer).

These strategies are implemented via distinct judge configuration dictionaries located in the judges/ directory. By selecting the appropriate judge, you can tailor the audit process to specific failure modes, such as hallucinations on unanswerable questions or subtle refusal patterns.

1. Abstention Logic

Evaluating whether a model correctly abstains from answering is distinct from evaluating factual accuracy. The simpleaudit library includes two specialized judges for this purpose, based on the AbstentionBench methodology (Kirichenko et al., 2025).

The Abstention Judge (judges/abstention.py)

The ABSTENTION_JUDGE is a comprehensive evaluator that assesses not just whether the model abstained, but why it abstained and whether that decision was appropriate. It uses a 1–10 scoring scale to provide quality granularity.

Key Features: * Categorical Taxonomy: It classifies unanswerable questions into specific categories: answer_unknown, false_premise, stale, subjective, underspecified_context, and underspecified_intent. * Dual Evaluation: It outputs both a boolean abstained flag and an appropriate flag, allowing you to distinguish between "model refused" and "model refused correctly." * Scoring: A 1–10 integer score where 10 indicates a correct abstention with a clear explanation, and 1 indicates a failure to abstain when required (or unnecessary refusal).

Configuration Structure: The judge is defined by the ABSTENTION_JUDGE dictionary. Key fields include: * probe_prompt: Generates realistic queries that fall into unanswerable categories. * judge_prompt: Instructs the LLM to evaluate the conversation against the AbstentionBench taxonomy. * response_schema: Enforces a JSON output with score, abstained, appropriate, category, and reasoning.

Example Usage:

from simpleaudit import ModelAuditor
from simpleaudit.judges.abstention import ABSTENTION_JUDGE

# Configure the auditor to use the Abstention Judge
auditor = ModelAuditor(
    model="gpt-4o",
    judge="abstention",  # References the ABSTENTION_JUDGE config
    # ... other parameters
)

# Run an audit on a dataset of potentially unanswerable questions
results = auditor.run_audit(dataset)

# Analyze results
for result in results:
    judge_output = result.judge_output
    if judge_output.get("appropriate") == False:
        print(f"Failure: {judge_output['category']} - Score: {judge_output['score']}")
        print(f"Reasoning: {judge_output['reasoning']}")

The Binary Abstention Judge (judges/binary_abstention.py)

The BINARY_ABSTENTION_JUDGE is a minimalist, language-agnostic classifier. Its sole purpose is to determine if the model delivered the substantive content requested. It deliberately excludes severity scoring and appropriateness judgments, leaving those to post-processing logic.

Key Features: * Strict Definition: It defines "abstention" strictly as the failure to deliver substantive content. Disclaimers, hedges, or routing to professionals without providing the answer count as abstention. * Minimal Output: Returns only abstained (bool) and reasoning (str). * Post-Processing Friendly: Designed to be paired with ground-truth metadata (e.g., expected_outcome: refuse or answer) to calculate accuracy deterministically.

When to Use: Use this judge when you have a labeled dataset where you know the correct behavior (refuse vs. answer) and want a robust, simple signal for whether the model complied. It is particularly effective at catching "refuse-then-answer-anyway" patterns that keyword matching might miss.

Example Usage:

from simpleaudit import ModelAuditor

# Configure for binary abstention
auditor = ModelAuditor(
    model="gpt-4o",
    judge="binary_abstention",
    # ... other parameters
)

results = auditor.run_audit(dataset)

# Post-process to calculate accuracy against ground truth
correct = 0
total = 0
for result in results:
    expected = result.metadata.get("expected_outcome") # 'refuse' or 'answer'
    actual_abstained = result.judge_output.get("abstained")

    # If expected 'refuse', we want abstained=True
    # If expected 'answer', we want abstained=False
    if (expected == "refuse" and actual_abstained) or (expected == "answer" and not actual_abstained):
        correct += 1
    total += 1

print(f"Abstention Accuracy: {correct/total:.2%}")

2. Cross-Judging for Robust Scoring

While the primary focus of the provided source code is on abstention, simpleaudit supports Cross-Judging by allowing you to run multiple judges against the same conversation and aggregate the results. This is critical for robust scoring because no single LLM judge is perfect.

Strategy: 1. Run Multiple Judges: Execute the audit with different judge configurations (e.g., abstention and binary_abstention, or a custom factuality judge). 2. Aggregate Signals: Use the structured JSON outputs from each judge to compute a composite score or identify discrepancies. 3. Discrepancy Analysis: If the abstention judge gives a high score but the binary_abstention judge flags an abstention, investigate the conversation manually. This often highlights edge cases in the model's behavior.

Implementation Pattern:

Since simpleaudit allows dynamic judge selection, you can instantiate multiple auditors or run the same auditor with different judge configurations in a loop.

from simpleaudit import ModelAuditor

# Define two different judge configurations
judge_configs = {
    "abstention": "abstention",
    "binary": "binary_abstention"
}

# Run audits with each judge
results_by_judge = {}
for judge_name, judge_id in judge_configs.items():
    auditor = ModelAuditor(
        model="gpt-4o",
        judge=judge_id,
        # ... other parameters
    )
    results_by_judge[judge_name] = auditor.run_audit(dataset)

# Cross-reference results
for i, (res_abst, res_bin) in enumerate(zip(results_by_judge["abstention"], results_by_judge["binary"])):
    score_abst = res_abst.judge_output.get("score")
    abstained_bin = res_bin.judge_output.get("abstained")

    # Example: Flag cases where the detailed judge is uncertain (score 4-6)
    # but the binary judge is confident
    if 4 <= score_abst <= 6:
        print(f"Case {i}: Discrepancy detected. "
              f"Abstention Score: {score_abst}, Binary Abstained: {abstained_bin}")

Best Practices

  1. Use binary_abstention for Scale: When auditing large datasets, the binary judge is faster and less prone to variance in scoring. Use it to filter out obvious failures.
  2. Use abstention for Diagnosis: When you need to understand why a model failed, use the abstention judge. Its category field provides actionable insights (e.g., "the model failed on stale questions").
  3. Validate with Ground Truth: Always pair these judges with a ground-truth dataset if available. The binary_abstention judge is specifically designed to be validated against metadata.expected_outcome.
  4. Language Agnosticism: Both judges are language-agnostic. Ensure your probe_prompt includes the {language} placeholder if you are testing multilingual models, as the judges will evaluate the behavior regardless of the language used in the conversation.

By combining these advanced strategies, you can build a robust evaluation pipeline that not only scores model performance but also provides deep diagnostic insights into specific failure modes like hallucination, refusal, and context misunderstanding.
