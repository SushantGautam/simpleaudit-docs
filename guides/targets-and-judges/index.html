    Targets And Judges

    SimpleAudit separates two concerns in every audit run:

    • The target — the system under test. It receives the auditor's probe messages and returns answers. This can be an LLM endpoint, an external HTTP application, or an in-process Python callable.
    • The judge — the evaluator that grades each conversation after the scenario ends. You pick a built-in judge by name, or build your own from criteria text using the compose helpers.

    This page covers how to configure both. See Auditing Basics for what a run does end-to-end, and Custom Judges for the deeper mechanics of writing judge criteria.

    The Target protocol

    Every target implements the Target protocol from simpleaudit/targets/base.py. It is a single async method:

    async def send(
    self,
    *,
    system: Optional[str] = None,
    user: str,
    history: Optional[List[Dict[str, Any]]] = None,
    file_uri: Optional[Union[str, List[str]]] = None,
    documents: Optional[List[Union[str, Dict[str, Any]]]] = None,
    response_format: Optional[Dict[str, Any]] = None,
    params: Optional[Dict[str, Any]] = None,
    context: Optional[TargetContext] = None,
) -> TargetResponse

    Two dataclasses accompany it:

    • TargetResponse — the normalized result of one send. Fields: content (the reply text), raw (unparsed payload, e.g. the full JSON body of an HTTP response), input_tokens / output_tokens (None when the target does not report usage — callers must treat None as "unknown", never zero), and decision (a decision model's structured answer; None for all other targets).
    • TargetContext — per-turn context passed into send(). Fields: audit_run_id, scenario_run_id, turn_id, trace_headers (W3C trace headers such as {"traceparent": "00-...-...-01"} to forward to the system under test), and extra (free-form metadata). All fields are optional.

    Built-in implementations:

    Class What it wraps
    ModelTarget An LLM endpoint via an AnyLLM client
    HTTPAppTarget An external application over HTTP (black-box)
    CallableTarget An in-process Python callable
    DecisionTarget A decision model over a System One endpoint

    ModelTarget

    ModelTarget is the historical default target. It has two construction modes:

    Client mode — pass an AnyLLM client plus a model name. send() builds the OpenAI-style message list and calls client.acompletion with retry logic:

    from simpleaudit import ModelTarget

target = ModelTarget(client=my_anyllm_client, model="gpt-4o")
response = await target.send(user="What is 2+2?")
print(response.content, response.input_tokens, response.output_tokens)

    Constructor signature:

    ModelTarget(
    client=None,
    model=None,
    *,
    transport=None,
    max_retries=0,
    retry_backoff=0.5,
)

    It raises ValueError if neither client nor transport is given. The client and model values are exposed as read-only properties. When the per-turn TargetContext carries trace_headers, they are merged into params["extra_headers"] so the outgoing call propagates the W3C trace context (see Tracing And Observability).

    Transport mode — pass a transport async callable that already knows how to turn (system, user, history, ...) into a TargetResponse; send() delegates to it directly, keeping one source of truth for message building and retries while routing through the Target protocol.

    HTTPAppTarget

    HTTPAppTarget audits systems that are not a bare LLM endpoint: an agent service, a RAG app, an Open WebUI instance, a company API. SimpleAudit sends the probe as an HTTP request and reads the answer out of the response using response_path. No instrumentation on the target is required.

    from simpleaudit import HTTPAppTarget

target = HTTPAppTarget(
    url="https://agent.example.com/chat",
    # dotted path into the JSON response, e.g. "choices.0.message.content"
    response_path="answer",
    headers={"Authorization": "Bearer sk-..."},
    timeout=60.0,
)

    Key constructor parameters:

    • url (required), method (default "POST"), headers, timeout (default 60.0).
    • request_template: a dict deep-copied as the base of every request body.
    • message_field: where the probe text goes in the body (default "message"). Use "messages" for OpenAI-style chat bodies — the current user turn is appended to any prior history as {"role": "user", "content": user}.
    • response_path: dotted path (e.g. "choices.0.message.content") resolved in the JSON response to extract the answer text. Non-string values are JSON-encoded.
    • documents_field: where a context-grounding run places its retrieval documents (text only). If documents are supplied but this is unset, the run fails loudly — an HTTP app must never be probed without its intended context.
    • token_paths: optional tuple like ("usage.prompt_tokens", "usage.completion_tokens") to extract token counts from the response. Otherwise tokens stay None.
    • client: an optional pre-built async HTTP client (anything with request(...) and aclose()); when omitted, an httpx.AsyncClient is created per call.

    Correlation is optional: when the TargetContext carries trace_headers or ids, they are forwarded as request headers (X-SimpleAudit-Turn-ID, X-SimpleAudit-Scenario-Run-ID, X-SimpleAudit-Run-ID), so an instrumented target can link its OTel spans back to this audit turn.

    Wiring a target into an auditor

    There are two entry points:

    Auditor — the target-agnostic primary class. It accepts any Target and any judge configuration, and delegates to the full ModelAuditor engine. When an explicit target is provided, no AnyLLM target client is created, so no API key or network access is needed for the (unused) model target:

    import asyncio
from simpleaudit import Auditor, HTTPAppTarget

auditor = Auditor(
    target=HTTPAppTarget(url="https://agent.example.com/chat", response_path="answer"),
    judge_model="gpt-4o",
    judge_provider="openai",
    judge_api_key="sk-...",
)
results = asyncio.run(auditor.run_async(scenarios=[
    {"name": "Test", "description": "A test scenario."},
]))
print(results.summary())

    Auditor(target=None) raises ValueError. Its target and engine properties expose the target and the underlying ModelAuditor.

    ModelAuditor.set_target() — on a ModelAuditor instance, the target property defaults to a ModelTarget wrapping target_client; calling set_target(custom) overrides it with any Target implementation. This is the extension point for auditing non-model systems ffrom simpleaudit import ModelAuditor, CallableTarget

## Built-in judges

Judge configurations live in `simpleaudit/judges`. Each config declares:

- `output` — the shape of its grade: `"severity"` (the critical/high/medium/low/pass
  ladder), `"score"` (1–10, with severity derived by the framework), `"binary"`
  (a yes/no classification), `"checklist"` (per-expectation items), or
  `"grounding"` (document-mark based findings).
- `criteria` — what to evaluate, in plain words.
- `format_prompt` — the output contract (JSON the judge must emit).
- `judge_prompt` — `criteria + format_prompt` joined.

    List what is available at runtime:

    from simpleaudit.judges import list_judge_configs

for name, description in list_judge_configs().items():
    print(f"{name}: {description}")

    Registered built-ins include:

    Name Output Notes
    safety severity Constitutional AI safety evaluation (Bai et al., 2022)
    abstention score Refusal/abstention appropriateness, AbstentionBench taxonomy; score 1–10 with abstained/appropriate flags
    helpfulness score MT-Bench dimensions; 1–10 with relevance, accuracy, clarity, completeness sub-scores
    factuality score Hallucination/factual-error detection; 1–10 with verdict and error lists
    harm severity HELM Safety harm categorisation across six harm types
    helsedir_sexhealth_no severity Norwegian sexual-health judge for young users (generic variant)
    helsedir_sexhealth_no_rag severity Same, RAG framing for bots with a fixed source corpus
    binary_abstention binary Language-agnostic yes/no: did the model abstain? Emits {abstained, reasoning}, no severity
    checklist checklist Evidence-anchored met/violated per expected behaviour with verified quotes; scenarios without expectations fall back to the default judge
    choice_match code-only Exact-match grading of a decision question; calls no judge model and creates no judge client
    groundedness grounding What the answer claimed and which documents it rejected; built per scenario
    fact_check code-assisted Learned-head fact verification against scenario facts (experimental, disabled by default)

    Score-based judges (abstention, helpfulness, factuality) emit a 1–10 score and no severity; the framework derives AuditResult.severity from the score (9–10 pass, 7–8 low, 5–6 medium, 3–4 high, 1–2 critical) so summaries and plots stay meaningful.

    Configs may also carry hooks read by ModelAuditor: postprocess(judgment, *, conversation, expected_behavior, scenario_meta) transforms the parsed judge output; requires_expected_behavior=True routes scenarios without expected_behavior to the default judge; and grade(*, conversation, expected_behavior, scenario_meta) replaces the judge call altogether (code-only judging, as in choice_match).

Signature:

```python
build_judge(
    output,            # "severity" | "score" | "binary" | "checklist"
    criteria,          # what to evaluate (required)
    *,
    dimensions=(),     # score only: names of 1-10 dimensions; empty = one overall score
    question=None,     # binary only: the yes/no question
    pass_when=True,    # binary only: the answer that passes (True = yes)
    probe_prompt=None, # how the auditor model writes user turns
    name="Custom judge",
)

    For score with dimensions, the JSON keys come from dimension_key(name); names that normalize to reserved keys (score, feedback, severity, summary), collide, or contain no letters/digits raise ValueError. For binary, a missing question or a non-boolean pass_when raises ValueError.

    customize_judge

    Copies a built-in (or composed) judge with new criteria and/or probe prompt, keeping the base's format, fields, and post-processing intact:

    from simpleaudit.judges import customize_judge

# Still emits a harm category, but with your own criteria wording
judge = customize_judge("harm", criteria="Focus on financial harm only.")

    Arguments left as None keep the base's value. It raises ValueError if the base has no format_prompt (so its criteria cannot be replaced) or if the base grades in code (no criteria to replace).
