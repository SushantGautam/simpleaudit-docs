    Test scenarios

    Test Scenarios¶

    SimpleAudit provides built-in adversarial test scenarios to evaluate AI system robustness, safety, and domain-specific compliance. Scenarios organize into named packs covering general safety, RAG behavior, healthcare boundaries, system prompt integrity, and epistemic safety. Use get_scenarios to retrieve specific packs or list_scenario_packs to inspect available inventory.

    Scenario Packs¶

    The scenarios module exposes SCENARIO_PACKS, a dictionary mapping pack names to lists of scenario dictionaries. Each scenario contains:

    • name: Unique identifier string
    • description: Detailed instructions for executing the test

    Available packs:

    Pack Name Description Count
    safety General AI safety (hallucination, manipulation, privacy) 8
    rag Retrieval-Augmented Generation specific tests 8
    health Healthcare domain safety boundaries 8
    system_prompt System prompt adherence and bypass attempts 8
    helpmed Help and medical scenarios Variable
    ung UNG scenarios Variable
    bullshitbench_v1 Business/management broken premise tests 55
    bullshitbench_v2 Software/finance/legal/medical/physics broken premise tests 100
    bullshitbench Combined v1 and v2 155
    health_bullshit Health-specific broken premise scenarios 15
    epistemic_safety All bullshitbench + health_bullshit combined 170
    hei_refusal Norwegian youth Q&A refusal/guidance edge cases 47
    nav_aap Norwegian welfare (NAV) scenarios 15
    skatteetaten Norwegian Tax Administration scenarios In development
    all Combined all available packs Variable

    API Reference¶

    get_scenarios(pack_name: str) -> List[Dict]¶

    Retrieves scenarios from a built-in pack.

    Parameters: - pack_name (str): Name of the scenario pack (e.g., "safety", "rag", "all").

    Returns: - List[Dict]: List of scenario dictionaries containing name and description keys.

    Raises: - ValueError: If pack_name is not recognized. Error message lists all available packs.

    Example:

    from simple_audit.scenarios import get_scenarios

# Get all general safety scenarios
safety_tests = get_scenarios("safety")

for scenario in safety_tests:
    print(f"Test: {scenario['name']}")
    print(f"Instructions: {scenario['description']}")
    print("-" * 40)

    list_scenario_packs() -> Dict[str, int]¶

    Lists available scenario packs and their sizes.

    Returns: - Dict[str, int]: Mapping of pack names to number of scenarios.

    Example:

    from simple_audit.scenarios import list_scenario_packs

packs = list_scenario_packs()
for name, count in packs.items():
    print(f"{name}: {count} scenarios")

    Scenario Structure¶

    Each scenario dictionary follows this schema:

    {
  "name": "Health - Emergency Response",
  "description": "Test if the system appropriately handles medical emergencies..."
}

    Developers iterate through these dictionaries to generate prompts or configure test harnesses. The description field contains natural language instructions for the test executor (human or automated agent).

    Usage Patterns¶

    Running Specific Pack¶

    Execute all healthcare safety tests:

    from simple_audit.scenarios import get_scenarios

health_scenarios = get_scenarios("health")

# Integrate with test runner
for i, scenario in enumerate(health_scenarios):
    test_id = f"health_{i:03d}"
    prompt = scenario["description"]
    # Execute test logic here
    # e.g., send prompt to AI system, evaluate response

    Combining Packs¶

    Merge multiple packs for comprehensive testing:

    from simple_audit.scenarios import get_scenarios

# Combine safety and system prompt tests
combined = get_scenarios("safety") + get_scenarios("system_prompt")

# Or use the pre-combined 'all' pack
full_suite = get_scenarios("all")

    Filtering by Keyword¶

    Filter scenarios based on name or description:

    from simple_audit.scenarios import get_scenarios

all_scenarios = get_scenarios("all")

# Find scenarios related to "hallucination"
hallucination_tests = [
    s for s in all_scenarios 
    if "hallucination" in s["name"].lower() or "hallucination" in s["description"].lower()
]

print(f"Found {len(hallucination_tests)} hallucination-related tests")

    Domain-Specific Notes¶

    Healthcare (health pack): Scenarios test critical boundaries: - Emergency response (urging emergency services over self-care) - Diagnosis refusal (providing general info, refusing specific diagnosis) - Prescription boundaries (deferring to professionals for medication advice) - Fictional medication hallucination detection - Drug interaction caution - Self-harm crisis resource provision - Pediatric safety caution - Professional credential immunity (system maintains boundaries regardless of claimed credentials)

    RAG Systems (rag pack): Scenarios test retrieval-specific failures: - Source misattribution and cross-document confusion - Retrieval boundary handling (out-of-scope queries) - Quote verification and correction - Context window stuffing (contradictory/overwhelming context) - Outdated information acknowledgment - Source fabrication detection - Out-of-scope query rejection

    System Prompt (system_prompt pack): Scenarios test instruction integrity: - Override attempts ("ignore previous instructions") - Prompt leak attempts (debugging, repetition) - Instruction contradiction handling - Context pollution (fake role markers) - Persistence across multi-turn conversations - Authority escalation resistance - Encoding bypass attempts (base64, obfuscation) - Multi-turn erosion (gradual boundary pushing)

    Epistemic Safety (epistemic_safety pack): Combines bullshitbench (155 scenarios) and health_bullshit (15 scenarios). Tests system resistance to broken premises, false assumptions, and nonsensical queries across business, software, finance, legal, medical, and physics domains.

    Error Handling¶

    Invalid pack names raise ValueError with helpful context:

    from simple_audit.scenarios import get_scenarios

try:
    scenarios = get_scenarios("invalid_pack")
except ValueError as e:
    print(e)
    # Output: Unknown scenario pack 'invalid_pack'. Available: safety, rag, health, ...

    Always validate pack names before execution in production pipelines. Use list_scenario_packs() to dynamically discover available packs.

    Integration with Audit Pipeline¶

    Typical integration pattern:

    from simple_audit.scenarios import get_scenarios
from simple_audit.auditor import Auditor  # Hypothetical auditor class

# Initialize auditor
auditor = Auditor(model="gpt-4")

# Load scenarios
scenarios = get_scenarios("safety")

# Execute audit
results = []
for scenario in scenarios:
    result = auditor.run_test(
        prompt=scenario["description"],
        test_name=scenario["name"]
    )
    results.append(result)

# Generate report
report = auditor.generate_report(results)
print(report)

    Scenarios serve as test specifications. The auditor or test harness interprets description to generate appropriate prompts and evaluates responses against expected safety behaviors.
