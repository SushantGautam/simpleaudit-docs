    Test Scenarios¶

    SimpleAudit provides built-in adversarial probes, health/safety benchmarks, and structured scenario packs for auditing LLM behavior. These packs test hallucination, safety boundaries, RAG integrity, and epistemic honesty. Use scenarios module to retrieve predefined test cases for automated auditing.

    Module Overview¶

    The scenarios package exports scenario packs as lists of dictionaries. Each scenario defines a test case with specific expected behaviors. Packs cover general safety, RAG systems, healthcare, and domain-specific edge cases (Norwegian welfare, youth advice).

    Key exports: * SCENARIO_PACKS: Dictionary mapping pack names to scenario lists. * get_scenarios(pack_name): Retrieves scenarios for a specific pack. * list_scenario_packs(): Returns dictionary of pack names and scenario counts.

    Scenario Structure¶

    Scenarios follow schema_version: "2.0". Basic packs (safety, rag, health) use simple structure. Advanced packs (bullshitbench, hei_refusal) use detailed metadata.

    Basic Structure¶

    Used by safety, rag, health packs.

    {
    "name": "Scenario Name",
    "description": "Detailed explanation of test objective and expected behavior."
}

    Advanced Structure¶

    Used by bullshitbench, health_bullshit, hei_refusal, helpmed packs.

    {
    "schema_version": "2.0",
    "name": "Unique Identifier",
    "description": "Summary of test case.",
    "test_prompt": "Exact prompt sent to LLM.",
    "language": "en",
    "expected_behavior": [
        "Behavior 1: e.g., 'Identify incoherent premise'",
        "Behavior 2: e.g., 'NOT provide direct answer'",
        "Behavior 3: e.g., 'Explain why concept does not apply'"
    ],
    "category": "Main Category (e.g., 'Harmful Content')",
    "subcategory": "Specific Subcategory (e.g., 'Dangerous Advice')",
    "severity": "low | medium | high | critical",
    "source": {
        "type": "synthetic | adapted | real_case",
        "origin": "Source description or URL",
        "inspiration": "Context for scenario creation"
    },
    "metadata": {
        "author": "Author Name",
        "date_created": "YYYY-MM-DD",
        "rationale": "Explanation of why this scenario tests specific failure mode",
        "tags": ["tag1", "tag2"],
        "variations": [
            {
                "test_prompt": "Alternative prompt",
                "note": "Context for variation"
            }
        ]
    }
}

    API Reference¶

    get_scenarios(pack_name: str) -> List[Dict]¶

    Retrieves list of scenario dictionaries for specified pack.

    Parameters: * pack_name (str): Name of scenario pack. Must match key in SCENARIO_PACKS.

    Returns: * List[Dict]: List of scenario objects.

    Raises: * ValueError: If pack_name not recognized. Error message lists available packs.

    Example:

    from simpleaudit.scenarios import get_scenarios

# Get all safety scenarios
safety_tests = get_scenarios("safety")
print(f"Loaded {len(safety_tests)} safety scenarios")

# Get epistemic safety tests (bullshitbench + health)
epistemic_tests = get_scenarios("epistemic_safety")

    list_scenario_packs() -> Dict[str, int]¶

    Lists all available scenario packs and their sizes.

    Returns: * Dict[str, int]: Mapping of pack names to scenario counts.

    Example:

    from simpleaudit.scenarios import list_scenario_packs

packs = list_scenario_packs()
for name, count in packs.items():
    print(f"{name}: {count} scenarios")

    Best Practices¶

    1. Use all pack for comprehensive audits: Covers safety, RAG, health, and domain-specific cases.
    2. Filter by severity: Prioritize high and critical severity scenarios for production readiness checks.
    3. Leverage expected_behavior: Use list of expected behaviors as checklist for automated judges.
    4. Handle variations: Advanced packs include prompt variations. Test all variations to ensure robustness against rephrasing.
    5. Norwegian Packs: hei_refusal and nav_aap contain Norwegian text. Ensure LLM supports Norwegian or translate prompts carefully.
