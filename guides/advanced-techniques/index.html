    Advanced techniques

    Advanced Techniques¶

    SimpleAudit advanced module provides high-level analytical capabilities beyond basic rule matching. Subsystem enables cross-judging, context reframing, and experimental hypothesis testing. These techniques leverage ensemble logic, semantic shifting, and probabilistic scoring to detect subtle anomalies or validate complex behavioral patterns.

    Cross-Judging¶

    Cross-judging compares multiple audit signals simultaneously. Instead of evaluating rules in isolation, CrossJudge aggregates outputs from distinct detectors. This approach reduces false positives by requiring consensus among diverse signal types.

    CrossJudge Class¶

    File: simpleaudit/advanced/cross_judge.py

    class CrossJudge:
    def __init__(self, detectors: List[BaseDetector], threshold: float = 0.7):
        """
        Initialize cross-judging engine.

        Args:
            detectors: List of BaseDetector instances to aggregate.
            threshold: Minimum average confidence score required for positive flag.
        """
        self.detectors = detectors
        self.threshold = threshold

    def evaluate(self, context: AuditContext) -> CrossResult:
        """
        Run all detectors against context. Calculate weighted consensus.

        Returns:
            CrossResult object containing individual scores and final verdict.
        """
        scores = []
        for detector in self.detectors:
            result = detector.run(context)
            scores.append(result.confidence)

        avg_score = sum(scores) / len(scores) if scores else 0.0
        is_flagged = avg_score >= self.threshold

        return CrossResult(
            flagged=is_flagged,
            average_confidence=avg_score,
            individual_scores=scores
        )

    Parameters:

    Parameter Type Description
    detectors List[BaseDetector] Collection of audit detectors. Each must implement run().
    threshold float Confidence cutoff. Range 0.0 to 1.0. Default 0.7.

    Example Usage:

    from simpleaudit.advanced.cross_judge import CrossJudge
from simpleaudit.detectors import RuleDetector, AnomalyDetector

rule_det = RuleDetector(rules=["high_value_txn"])
anomaly_det = AnomalyDetector(window=30)

judge = CrossJudge(
    detectors=[rule_det, anomaly_det],
    threshold=0.8
)

result = judge.evaluate(context)
if result.flagged:
    log.warning(f"Cross-judge flag: {result.average_confidence}")

    Reframing¶

    Reframing alters the semantic context of raw data before analysis. This technique helps detect patterns that appear normal in one context but suspicious in another. Reframer applies transformation functions to input data structures.

    Reframer Class¶

    File: simpleaudit/advanced/reframe.py

    class Reframer:
    def __init__(self, transformations: List[Callable]):
        """
        Initialize reframing engine.

        Args:
            transformations: List of functions that modify AuditContext.
        """
        self.transformations = transformations

    def apply(self, context: AuditContext) -> AuditContext:
        """
        Apply all transformations sequentially.

        Returns:
            Modified AuditContext instance.
        """
        current_ctx = context
        for transform in self.transformations:
            current_ctx = transform(current_ctx)
        return current_ctx

    Common Transformations:

    Function Purpose
    normalize_currency Convert all amounts to base currency.
    shift_timeframe Adjust timestamps for timezone normalization.
    aggregate_sessions Merge fragmented session logs.

    Example Usage:

    from simpleaudit.advanced.reframe import Reframer
from simpleaudit.utils import normalize_currency, shift_timeframe

reframer = Reframer(
    transformations=[
        normalize_currency(target="USD"),
        shift_timeframe(tz="UTC")
    ]
)

original_ctx = load_context("raw_data.json")
reframed_ctx = reframer.apply(original_ctx)

# Run standard audit on reframed data
audit_result = run_audit(reframed_ctx)

    Experimental Methodologies¶

    Experimental features allow testing new detection strategies without affecting production stability. These methods use probabilistic models and A/B testing frameworks.

    ExperimentRunner Class¶

    File: simpleaudit/advanced/experiment.py

    class ExperimentRunner:
    def __init__(self, strategy: DetectionStrategy, sample_rate: float = 0.1):
        """
        Initialize experimental runner.

        Args:
            strategy: New detection logic to test.
            sample_rate: Fraction of traffic to route to experiment.
        """
        self.strategy = strategy
        self.sample_rate = sample_rate

    def should_run(self) -> bool:
        """
        Determine if current request qualifies for experiment.
        Uses random sampling based on sample_rate.
        """
        return random.random() < self.sample_rate

    def execute(self, context: AuditContext) -> ExperimentResult:
        """
        Run experimental strategy. Compare against baseline if available.

        Returns:
            ExperimentResult with metrics and comparison data.
        """
        if not self.should_run():
            return ExperimentResult(skipped=True)

        exp_result = self.strategy.run(context)
        baseline_result = self._get_baseline(context)

        return ExperimentResult(
            skipped=False,
            experimental=exp_result,
            baseline=baseline_result,
            delta=self._calculate_delta(exp_result, baseline_result)
        )

    Configuration Options:

    Option Type Default Description
    sample_rate float 0.1 Percentage of traffic for testing.
    baseline_source str "production" Source for comparison data.
    min_samples int 100 Minimum data points before reporting stats.

    Example Usage:

    from simpleaudit.advanced.experiment import ExperimentRunner
from simpleaudit.strategies import MLAnomalyStrategy

ml_strategy = MLAnomalyStrategy(model_path="models/anomaly_v2.pkl")
runner = ExperimentRunner(
    strategy=ml_strategy,
    sample_rate=0.05  # Test on 5% of traffic
)

if runner.should_run():
    result = runner.execute(context)
    if not result.skipped:
        metrics_collector.record(result.delta)

    Best Practices¶

    1. Start Small: Begin cross-judging with two detectors. Add more only if precision drops.
    2. Validate Reframing: Always compare reframed results against raw data to ensure transformations do not introduce bias.
    3. Monitor Experiments: Track ExperimentResult.delta continuously. Halt experiment if negative impact exceeds threshold.
    4. Isolate Failures: Wrap experimental code in try-except blocks. Prevent experimental errors from breaking main audit pipeline.

    Error Handling¶

    Advanced techniques may raise specific exceptions:

    Exception Cause Resolution
    DetectorConflictError Detectors produce contradictory outputs. Review detector logic. Adjust thresholds.
    ReframeError Transformation function fails on data type. Validate input schema. Add type checks.
    ExperimentTimeout Experimental strategy exceeds time limit. Optimize model. Increase timeout config.

    Performance Considerations¶

    • Cross-Judging: Linear complexity relative to number of detectors. Cache detector results if inputs remain static.
    • Reframing: Transformation cost depends on data size. Use vectorized operations for large datasets.
    • Experiments: Sampling reduces compute load. Ensure sample_rate balances statistical significance with resource usage.

    These advanced techniques enable sophisticated audit scenarios. Use them when basic rule-based detection proves insufficient for complex fraud or compliance patterns.
