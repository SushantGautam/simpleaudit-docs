    Judges system

    Judges System¶

    SimpleAudit judges evaluate model outputs using LLM-as-a-judge methodology. Judges score conversations against specific criteria, returning structured JSON assessments.

    Core Concepts¶

    Judges consist of three components:

    1. Probe Prompt: Instructions for the auditor LLM to generate realistic user queries.
    2. Judge Prompt: Instructions for the evaluator LLM to score the conversation.
    3. Output Schema: Defines the expected JSON structure for the evaluation result.

    Built-in judges map to established research methodologies:

    Judge Name Methodology Score Type Key Output Fields
    safety Constitutional AI (Bai et al., 2022) Severity severity, issues_found
    abstention AbstentionBench (Kirichenko et al., 2025) 1–10 score, abstained, category
    helpfulness MT-Bench (Zheng et al., 2023) 1–10 score, relevance, accuracy
    factuality G-Eval (Liu et al., 2023) 1–10 score, verdict, factual_errors
    harm HELM Safety (Liang et al., 2022) Severity harmful, category, severity
    binary_abstention Custom Minimal Boolean abstained, reasoning

    Usage¶

    Initialize ModelAuditor with a named judge or custom prompt.

    from simpleaudit import ModelAuditor

# Use built-in judge
auditor = ModelAuditor(
    model="gpt-4o",
    judge="helpfulness"
)

# Override probe prompt for specific testing angle
auditor = ModelAuditor(
    model="gpt-4o",
    judge="factuality",
    probe_prompt="Ask about obscure historical dates..."
)

# Fully custom judge
auditor = ModelAuditor(
    model="gpt-4o",
    judge_prompt="You are a tone evaluator. Score politeness 1-10..."
)

    API Reference¶

    simpleaudit.judges.get_judge(name)¶

    Retrieves built-in judge configuration.

    Parameters: * name (str): Judge identifier (e.g., "safety", "harm").

    Returns: * Dict[str, Any]: Configuration containing probe_prompt, judge_prompt, output_schema, source.

    Raises: * ValueError: If name not in JUDGE_CONFIGS.

    from simpleaudit.judges import get_judge

config = get_judge("safety")
print(config["description"])

    simpleaudit.judges.list_judge_configs()¶

    Lists available judge names and descriptions.

    Returns: * Dict[str, str]: Mapping of judge names to one-line descriptions.

    from simpleaudit.judges import list_judge_configs

for name, desc in list_judge_configs().items():
    print(f"{name}: {desc}")

    Judge Details¶

    Safety Judge¶

    Evaluates harm avoidance, boundaries, accuracy, transparency, manipulation resistance.

    Output Schema: * severity: critical | high | medium | low | pass * issues_found: List of specific problems * positive_behaviors: List of good practices * summary: Overall evaluation * recommendations: Suggested fixes

    Abstention Judge¶

    Assesses correct refusal of unanswerable questions. Categories: answer_unknown, false_premise, stale, subjective, underspecified_context, underspecified_intent, none.

    Output Schema: * score: 1–10 (10 = correct abstention with clear explanation) * abstained: Boolean * appropriate: Boolean (was decision correct?) * category: Unanswerable question type * reasoning: Explanation

    Helpfulness Judge¶

    Scores response quality across four dimensions: relevance, accuracy, clarity, completeness.

    Output Schema: * score: Float (average of four dimensions) * relevance: 1–10 * accuracy: 1–10 * clarity: 1–10 * completeness: 1–10 * feedback: Qualitative explanation

    Factuality Judge¶

    Detects hallucinations and factual errors using chain-of-thought reasoning.

    Output Schema: * score: 1–10 * verdict: accurate | partially_accurate | inaccurate * factual_errors: List of incorrect claims * unsupported_claims: List of ungrounded assertions * reasoning: Step-by-step analysis

    Harm Judge¶

    Categorizes harmful content across six types: violence, fraud, discrimination, sexual, harassment, deception.

    Output Schema: * harmful: Boolean * category: Harm type or none * severity: none | low | medium | high | critical * explanation: Classification rationale

    Binary Abstention Judge¶

    Language-agnostic classifier. Determines if model delivered substantive content. Ignores disclaimers/hedges.

    Output Schema: * abstained: Boolean (true if content not delivered) * reasoning: Short explanation with quote

    Note: This judge declares its own response_schema. No json_format override needed.

    Custom Judges¶

    Create custom judges by providing judge_prompt. The framework infers output schema from prompt instructions or defaults to generic structure.

    auditor = ModelAuditor(
    model="gpt-4o",
    judge_prompt="""
    Evaluate code quality.
    Return JSON:
    {
      "score": <int 1-10>,
      "bugs": ["<bug description>"],
      "style_issues": ["<issue>"]
    }
    """
)

    Configuration Structure¶

    All judges follow this internal structure:

    {
    "name": str,
    "description": str,
    "probe_prompt": str,      # Instructions for auditor LLM
    "judge_prompt": str,      # Instructions for evaluator LLM
    "output_schema": dict,    # Human-readable field descriptions
    "response_schema": dict,  # JSON Schema for validation (optional)
    "source": dict,           # Academic reference metadata
    "metadata": dict          # Version, author, date
}

    Best Practices¶

    1. Match Judge to Goal: Use safety for red-teaming, helpfulness for quality assurance, factuality for RAG systems.
    2. Customize Probes: Default probes are generic. Override probe_prompt to target specific vulnerabilities or domains.
    3. Validate Output: Judge outputs are JSON. Parse results programmatically for dashboards or alerts.
    4. Binary Abstention: Use binary_abstention when ground truth expected_outcome exists in scenario metadata. Compute appropriateness in post-processing.
