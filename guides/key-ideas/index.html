    Key ideas

    Key Ideas

    SimpleAudit operates on a dual-agent architecture designed to validate comparative LLM safety scoring without relying on ground-truth labels. The system separates the auditing process (probing the target model) from the evaluation process (judging the target's responses). This separation allows developers to define specific adversarial strategies via Scenarios and evaluation criteria via Judges.

    The Dual-Agent Architecture

    The core of the library is the ModelAuditor class, which orchestrates the interaction between two distinct LLM roles:

    1. The Target Model: The AI system under audit. It receives prompts generated by the auditor and produces responses.
    2. The Auditor (Probe) Model: An LLM that acts as a red-teamer. It generates follow-up questions or adversarial prompts based on the scenario description and the target's previous responses.
    3. The Judge Model: An LLM that evaluates the final conversation transcript against specific safety or quality criteria.

    This tripartite setup (Target, Auditor, Judge) is configured through the ModelAuditor constructor.

    Scenarios: Defining Adversarial Strategies

    Scenarios define what the auditor should test. They are structured as dictionaries containing a name and a description. The description serves as the instruction set for the auditor model, guiding it on how to probe the target.

    SimpleAudit provides several built-in scenario packs, accessible via the get_scenarios function.

    Available Scenario Packs

    You can list all available packs and their sizes using list_scenario_packs():

    from simpleaudit.scenarios import list_scenario_packs

packs = list_scenario_packs()
for name, count in packs.items():
    print(f"{name}: {count} scenarios")

    Key packs include: * safety: General AI safety scenarios (hallucinations, fictional content). * health: Healthcare domain scenarios (emergency response, diagnosis boundaries). * bullshitbench: Combined v1 and v2 BullshitBench scenarios for detecting nonsensical or fabricated claims. * hei_refusal: Norwegian youth Q&A refusal/guidance edge cases. * rag: RAG-specific scenarios (source misattribution).

    Retrieving Scenarios

    Use get_scenarios(pack_name) to retrieve a list of scenario dictionaries. If the pack name is invalid, a ValueError is raised listing available packs.

    from simpleaudit.scenarios import get_scenarios

# Retrieve the first 3 scenarios from the 'health' pack
health_scenarios = get_scenarios("health")[:3]

# Each scenario is a dict with 'name' and 'description'
print(health_scenarios[0]["name"])
print(health_scenarios[0]["description"])

    Judges: Defining Evaluation Criteria

    Judges define how the target's responses are evaluated. A judge configuration is a dictionary containing: * probe_prompt: Instructions for the auditor model on how to conduct the probe. * judge_prompt: Instructions for the judge model on how to score the conversation. * output_schema: The expected JSON structure for the judge's output. * source: Academic references for the evaluation methodology.

    Available Judges

    You can list all available judge configurations using list_judge_configs():

    from simpleaudit.judges import list_judge_configs

judges = list_judge_configs()
for name, desc in judges.items():
    print(f"{name}: {desc}")

    Key judges include: * safety: Constitutional AI safety evaluation (Bai et al., 2022). Outputs severity levels (critical, high, medium, low, pass). * factuality: G-Eval based hallucination detection (Liu et al., 2023). Outputs a score (1-10) and verdict. * abstention: Evaluates if the model appropriately refused or answered (Feng et al., 2024). * helpfulness: MT-Bench style response quality evaluation (Zheng et al., 2023). * binary_abstention: A language-agnostic binary classifier for refusal detection.

    Retrieving Judge Configs

    Use get_judge(name) to retrieve a specific judge configuration.

    from simpleaudit.judges import get_judge

safety_judge = get_judge("safety")
print(safety_judge["name"])
print(safety_judge["description"])

    Configuring the Audit

    The ModelAuditor class ties scenarios and judges together. You can use built-in judges by name or provide custom prompts.

    Using Built-in Judges

    When you specify a judge name (e.g., "safety"), the ModelAuditor automatically loads the corresponding probe_prompt and judge_prompt from the judge configuration.

    from simpleaudit import ModelAuditor
from simpleaudit.scenarios import get_scenarios

# Get scenarios
scenarios = get_scenarios("safety")[:2]

# Initialize auditor with built-in 'safety' judge
auditor = ModelAuditor(
    model="llama3.2:3b",       # Target model
    provider="ollama",
    judge_model="gemma3:latest", # Judge model
    judge_provider="ollama",
    judge="safety",             # Uses SAFETY_JUDGE config
    max_turns=3,
    verbose=True
)

# Run the audit
results = auditor.run(scenarios)

    Customizing Probes and Judges

    You can override the default prompts for a specific judge or provide fully custom prompts.

    1. Override Probe Prompt: Keep the judge's evaluation criteria but change how the auditor probes.
    2. Custom Judge Prompt: Provide a completely custom judge_prompt. This takes precedence over any named judge's judge_prompt.
    # Example: Using 'factuality' judge but with a custom probe strategy
auditor = ModelAuditor(
    model="llama3.2:3b",
    provider="ollama",
    judge_model="gemma3:latest",
    judge_provider="ollama",
    judge="factuality",
    probe_prompt="Ask specifically about dates and statistics to test factual accuracy.",
    max_turns=3
)

    If you provide a judge_prompt parameter, it overrides the judge_prompt from the named judge configuration. This allows for fully custom evaluation logic while potentially reusing the probe_prompt from a built-in judge.

    Running Experiments

    The ModelAuditor.run() method executes the audit for a list of scenarios. It returns an AuditResults object, which contains: * summary(): A high-level summary of the audit. * to_dict(): The full results in dictionary format. * save(filepath): Saves results to a JSON file. * plot(save_path): Generates visualizations of the results.

    For multi-model comparisons or repeated runs, use the AuditExperiment class, which supports n_repetitions and generates ModelStabilityReport objects to assess consistency.

    from simpleaudit.experiment import AuditExperiment

experiment = AuditExperiment(
    models=[
        {"name": "model_a", "model": "llama3.2:3b", "provider": "ollama"},
        {"name": "model_b", "model": "gemma3:latest", "provider": "ollama"}
    ],
    judge_model="gemma3:latest",
    judge_provider="ollama",
    judge="safety",
    n_repetitions=3
)

# Run async experiment
results = experiment.run_async(scenarios, max_turns=3)

    Key Takeaways

    1. Separation of Concerns: Scenarios define what to test; Judges define how to evaluate.
    2. Configurability: Both probes and judges can be customized via probe_prompt and judge_prompt parameters in ModelAuditor.
    3. Built-in Standards: SimpleAudit ships with academically grounded judges (Constitutional AI, G-Eval, MT-Bench) to ensure rigorous evaluation.
    4. Local-First: The framework is designed to work with local models (e.g., via Ollama) without requiring external API keys, ensuring privacy and minimal setup.
