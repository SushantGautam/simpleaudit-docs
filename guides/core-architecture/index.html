    Core architecture

    Core Architecture¶

    SimpleAudit core architecture centers immutable audit trail generation. System captures state changes, serializes events, stores records. Design prioritizes data integrity, tamper resistance, ease integration.

    System Overview¶

    Library operates event-driven model. Application code triggers audit events. SimpleAudit intercepts events, processes metadata, writes records. Data flow follows linear path:

    1. Event Capture: Application invokes audit method or decorator.
    2. Context Assembly: Library gathers user identity, timestamp, IP address, resource identifier.
    3. Serialization: Event data converts to canonical JSON format.
    4. Storage: Record persists to configured backend (database, file, or external service).
    5. Verification: Optional hash chain links new record to previous record, ensuring immutability.

    Modules interact through central AuditManager instance. This singleton manages configuration, backend connections, and event queue.

    Module Interactions¶

    Codebase divides into distinct modules:

    • simpleaudit/core/manager.py: Contains AuditManager class. Orchestrates audit lifecycle.
    • simpleaudit/core/event.py: Defines AuditEvent dataclass. Represents single audit record.
    • simpleaudit/backends/base.py: Abstract base class AuditBackend. Defines interface for storage implementations.
    • simpleaudit/backends/sql.py: SQL backend implementation.
    • simpleaudit/backends/file.py: File-based backend implementation.
    • simpleaudit/decorators.py: Provides @audit decorator for automatic event capture.

    AuditManager holds reference to active AuditBackend. Application code rarely interacts directly with backends. Instead, developers configure backend via manager initialization.

    Public API¶

    AuditManager¶

    Primary entry point for library functionality.

    from simpleaudit import AuditManager

manager = AuditManager(
    backend="sql",
    database_url="sqlite:///audit.db",
    hash_chain=True
)

    Parameters:

    Parameter Type Description
    backend str Backend type: "sql", "file", or custom class path.
    database_url str Connection string for SQL backends. Ignored for file backends.
    file_path str Output directory for file backends.
    hash_chain bool Enable cryptographic hash chaining for tamper detection. Default True.
    user_resolver Callable Function returning current user ID. Used for attribution.

    Methods:

    • log(action: str, resource: str, data: dict = None, user: str = None) -> AuditEvent: Records manual audit event.

      • action: String describing action (e.g., "create", "delete").
      • resource: Identifier of affected resource.
      • data: Optional dictionary of additional context.
      • user: Optional user ID. Defaults to user_resolver output.

    • verify_chain() -> bool: Validates integrity of hash chain. Returns True if all hashes match.

    • query(resource: str = None, user: str = None, limit: int = 100) -> list[AuditEvent]: Retrieves historical audit records. Filters by resource or user.

    AuditEvent¶

    Immutable dataclass representing single audit record.

    Attributes:

    Attribute Type Description
    id str Unique identifier (UUID).
    timestamp datetime ISO 8601 timestamp of event.
    user str User ID associated with event.
    action str Action performed.
    resource str Resource identifier.
    data dict Serialized event payload.
    previous_hash str Hash of previous record. None for first record.
    current_hash str SHA-256 hash of this record.

    @audit Decorator¶

    Automates event capture for function calls.

    from simpleaudit.decorators import audit

@audit(action="update", resource="user_profile")
def update_user_profile(user_id: int, new_data: dict):
    # Function logic here
    pass

    Decorator inspects function arguments. Maps parameters to data dictionary. Captures caller identity via user_resolver.

    Configuration Options¶

    Configuration occurs during AuditManager instantiation. No global configuration file required.

    Backend Specifics:

    • SQL Backend:

      • Requires database_url.
      • Supports SQLAlchemy-compatible databases (PostgreSQL, MySQL, SQLite).
      • Automatically creates audit_logs table if missing.
      • Schema includes columns: id, timestamp, user, action, resource, data_json, prev_hash, curr_hash.

    • File Backend:

      • Requires file_path.
      • Writes JSON Lines (.jsonl) files.
      • Rotates files daily. Filename format: audit_YYYY-MM-DD.jsonl.
      • Suitable for development or lightweight logging.

    Hash Chaining:

    When hash_chain=True, each AuditEvent includes previous_hash and current_hash.

    • current_hash = SHA-256(id + timestamp + user + action + resource + data + previous_hash).
    • First record has previous_hash = "0" * 64.
    • Enables detection of record modification or deletion.

    Data Flow Example¶

    Consider updating a user profile.

    1. Developer calls update_user_profile(123, {"name": "Alice"}).
    2. @audit decorator intercepts call.
    3. Decorator constructs AuditEvent:
      • action: "update"
      • resource: "user_profile"
      • data: {"user_id": 123, "new_data": {"name": "Alice"}}
      • user: Retrieved from user_resolver.
    4. AuditManager.log() serializes event.
    5. Backend writes record to storage.
    6. If hash chaining enabled, manager computes new hash.
    7. Function executes original logic.
    8. If exception occurs, decorator logs action="error" with traceback data.

    Error Handling¶

    Library raises AuditError for configuration or storage failures.

    • InvalidBackendError: Raised when backend string does not match known type.
    • StorageError: Raised when backend fails to write record.
    • ChainVerificationError: Raised by verify_chain() if hash mismatch detected.

    Application code should catch AuditError to handle logging failures gracefully. Audit failures should not crash primary application logic unless strict compliance required.

    Performance Considerations¶

    • Synchronous Writes: Default behavior writes synchronously. High-throughput applications may experience latency.
    • Async Support: AuditManager supports async backend implementations. Use await manager.log_async(...).
    • Batching: File backend buffers writes. SQL backend uses single transaction per event. Batch processing not currently supported for SQL backend.

    Security Notes¶

    • Hash chaining prevents undetected modification of stored records.
    • Does not prevent deletion of entire database or file.
    • Ensure storage backend has appropriate access controls.
    • data dictionary should not contain sensitive secrets (passwords, API keys). Sanitize input before logging.

    Integration Patterns¶

    Flask/FastAPI:

    Use middleware to capture HTTP requests.

    @app.before_request
def audit_request():
    manager.log(
        action="http_request",
        resource=request.path,
        data={"method": request.method, "ip": request.remote_addr}
    )

    Django:

    Use signals to audit model changes.

    from django.db.models.signals import post_save

def audit_post_save(sender, instance, created, **kwargs):
    manager.log(
        action="create" if created else "update",
        resource=sender.__name__,
        data={"pk": instance.pk}
    )

post_save.connect(audit_post_save, sender=MyModel)

    Summary¶

    SimpleAudit architecture separates event capture, serialization, and storage. AuditManager provides unified interface. Backends abstract persistence details. Hash chaining ensures data integrity. Developers configure manager, apply decorators or call log(), and retrieve records via query(). System designed for minimal intrusion into application code.
