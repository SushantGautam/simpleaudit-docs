Core architecture

Core Architecture

The simpleaudit library is designed to provide a lightweight, non-intrusive mechanism for tracking changes to Python objects. Its core architecture revolves around a centralized Audit Log that captures state transitions, ensuring that every modification to a monitored object is recorded with full context, including the timestamp, the user (if available), and the specific field changes.

The system is built upon three primary components: 1. AuditLog: The central registry that stores all recorded events. 2. AuditEntry: The data structure representing a single change event. 3. Auditable: A mixin or base class that instruments objects to automatically report changes to the AuditLog.

Data Flow

The auditing pipeline follows a unidirectional data flow:

  1. Initialization: An object is instantiated with the Auditable capability. During initialization, the object registers itself with the global AuditLog instance.
  2. State Capture: When an attribute of an Auditable object is modified, the __setattr__ method (or property setter) intercepts the change.
  3. Diff Calculation: The library compares the old value of the attribute with the new value. If a difference is detected, it prepares an AuditEntry.
  4. Logging: The AuditEntry is appended to the AuditLog. This operation is synchronous and in-memory by default, ensuring low latency.
  5. Retrieval: Developers can query the AuditLog to retrieve historical changes, filter by object, user, or time range, and export the data.

Key Components

AuditLog

The AuditLog class serves as the singleton container for all audit events. It manages the lifecycle of audit entries and provides query interfaces.

Class Definition:

class AuditLog:
    def __init__(self, max_entries: int = 1000):
        """
        Initializes the AuditLog.

        Args:
            max_entries: Maximum number of entries to keep in memory. 
                         Oldest entries are discarded when this limit is reached.
        """
        self._entries: deque[AuditEntry] = deque(maxlen=max_entries)
        self._lock = threading.Lock()

    def log(self, entry: AuditEntry) -> None:
        """
        Appends a new entry to the log.

        Args:
            entry: The AuditEntry instance to record.
        """
        with self._lock:
            self._entries.append(entry)

    def get_history(self, object_id: Optional[str] = None, 
                    limit: int = 100) -> List[AuditEntry]:
        """
        Retrieves audit history.

        Args:
            object_id: Filter by specific object ID. If None, returns all.
            limit: Maximum number of entries to return (most recent first).

        Returns:
            A list of AuditEntry objects.
        """
        with self._lock:
            if object_id:
                filtered = [e for e in self._entries if e.object_id == object_id]
            else:
                filtered = list(self._entries)

            # Return most recent first
            return list(reversed(filtered[-limit:]))

AuditEntry

An AuditEntry represents a single atomic change. It is an immutable dataclass to ensure data integrity once logged.

Class Definition:

from dataclasses import dataclass
from datetime import datetime
from typing import Any, Dict

@dataclass(frozen=True)
class AuditEntry:
    timestamp: datetime
    object_id: str
    field: str
    old_value: Any
    new_value: Any
    user: str = "system"

    def to_dict(self) -> Dict[str, Any]:
        """Converts the entry to a dictionary for serialization."""
        return {
            "timestamp": self.timestamp.isoformat(),
            "object_id": self.object_id,
            "field": self.field,
            "old_value": self.old_value,
            "new_value": self.new_value,
            "user": self.user
        }

Auditable

The Auditable class provides the instrumentation logic. It overrides __setattr__ to detect changes and triggers logging.

Class Definition:

class Auditable:
    _audit_log: AuditLog = None  # Class-level reference to global log

    def __init__(self, object_id: str, user: str = "system"):
        self._object_id = object_id
        self._user = user
        self._state: Dict[str, Any] = {}

        # Register with the global log if not already set
        if Auditable._audit_log is None:
            Auditable._audit_log = AuditLog()

    def __setattr__(self, name: str, value: Any) -> None:
        # Allow internal attributes to be set without auditing
        if name.startswith('_') and name not in ('_state',):
            super().__setattr__(name, value)
            return

        # Check if this is a new attribute or a change
        if name in self._state:
            old_value = self._state[name]
            if old_value != value:
                entry = AuditEntry(
                    timestamp=datetime.now(),
                    object_id=self._object_id,
                    field=name,
                    old_value=old_value,
                    new_value=value,
                    user=self._user
                )
                Auditable._audit_log.log(entry)

        # Update internal state
        self._state[name] = value
        super().__setattr__(name, value)

Usage Example

Below is a practical example demonstrating how to use simpleaudit to track changes in a User model.

from simpleaudit import Auditable, AuditLog

# Initialize the global audit log (optional if using defaults)
log = AuditLog(max_entries=500)
Auditable._audit_log = log

class User(Auditable):
    def __init__(self, user_id: str, username: str, email: str):
        super().__init__(object_id=user_id, user="admin")
        self.username = username
        self.email = email

# Create a user
user = User("user-123", "john_doe", "john@example.com")

# Modify the user
user.email = "john.new@example.com"
user.username = "jdoe"

# Retrieve audit history
history = log.get_history(object_id="user-123")

for entry in history:
    print(f"[{entry.timestamp}] User {entry.object_id}: "
          f"{entry.field} changed from '{entry.old_value}' to '{entry.new_value}' "
          f"by {entry.user}")

Expected Output:

[2023-10-27T10:00:00.123456] User user-123: email changed from 'john@example.com' to 'john.new@example.com' by admin
[2023-10-27T10:00:00.123500] User user-123: username changed from 'john_doe' to 'jdoe' by admin

Configuration Options

The simpleaudit library offers minimal configuration to maintain simplicity, but the following parameters can be adjusted:

Parameter Location Default Description
max_entries AuditLog.__init__ 1000 The maximum number of audit entries to retain in memory. Older entries are automatically purged.
user Auditable.__init__ "system" The default user identifier associated with changes made by this object instance.

Thread Safety

The AuditLog class uses a threading.Lock to ensure that concurrent writes to the log are safe. This makes simpleaudit suitable for multi-threaded applications where multiple threads may modify auditable objects simultaneously. However, the Auditable class itself is not thread-safe; if multiple threads modify the same object instance, external synchronization is required to prevent race conditions in the __setattr__ logic.

Limitations

  1. In-Memory Storage: By default, audit logs are stored in memory. For persistent auditing, you must implement a custom backend by subclassing AuditLog or hooking into the log method to write to a database or file.
  2. No Nested Object Tracking: The library tracks changes to top-level attributes. If an attribute is a complex object (e.g., a list or dictionary), the entire object is compared for equality. Deep diffing of nested structures is not supported.
  3. Performance Overhead: Every attribute assignment triggers a comparison and potential logging. For high-frequency updates, consider batching changes or disabling auditing for specific fields.

Best Practices

  • Unique Object IDs: Ensure that object_id is unique across your application to facilitate accurate filtering in get_history.
  • Immutable Types: Prefer immutable types (strings, numbers, tuples) for audited fields to ensure reliable equality checks.
  • Explicit User Context: Pass the user parameter explicitly when creating Auditable instances in web applications to accurately attribute changes to the logged-in user.
