    Core architecture

    Core Architecture¶

    SimpleAudit provides lightweight, deterministic audit logging for Python applications. System captures state changes, user actions, and system events. Design prioritizes minimal overhead, data integrity, and ease of integration.

    Design Principles¶

    • Non-Invasive: Library hooks into application logic without altering core business logic.
    • Immutable Records: Once logged, audit entries remain immutable. Prevents tampering.
    • Pluggable Storage: Default in-memory storage. Support for SQL, NoSQL, or file-based backends via adapter pattern.
    • Asynchronous Safe: Operations thread-safe. Suitable for multi-threaded or async environments.

    Module Structure¶

    Core components reside in simple_audit package.

    Module Responsibility
    core.py AuditLogger class, event definitions, internal state management.
    storage.py StorageBackend abstract base class, InMemoryStorage implementation.
    models.py AuditEvent dataclass, Actor model, Resource model.
    utils.py Hashing utilities, timestamp generation, ID generation.

    Data Flow¶

    1. Event Creation: Application calls logger.log() or decorator wraps function.
    2. Context Capture: AuditLogger captures actor, resource, action, and metadata.
    3. Serialization: Event converts to immutable AuditEvent object.
    4. Persistence: StorageBackend persists event.
    5. Retrieval: Query interface fetches events for review or analysis.

    Core Classes¶

    AuditLogger¶

    Main entry point. Manages logging lifecycle.

    File: simple_audit/core.py

    Constructor:

    class AuditLogger:
    def __init__(self, storage: StorageBackend = None, actor: Actor = None):
        """
        Initialize logger.

        Args:
            storage: StorageBackend instance. Defaults to InMemoryStorage.
            actor: Default Actor for events. Can be overridden per event.
        """

    Methods:

    • log(action: str, resource: Resource, metadata: dict = None, actor: Actor = None) -> AuditEvent
    • Records single event.
    • action: String identifier (e.g., "create", "update").
    • resource: Object identifying target entity.
    • metadata: Optional key-value pairs for extra context.
    • actor: Optional override for default actor.

    • Returns: AuditEvent instance.

    • query(filter: dict = None, limit: int = 100) -> list[AuditEvent]

    • Retrieves events.
    • filter: Dict matching event attributes (e.g., {"action": "delete"}).
    • limit: Max events to return.

    AuditEvent¶

    Immutable dataclass representing single audit record.

    File: simple_audit/models.py

    Fields:

    • id: Unique string identifier (UUID).
    • timestamp: ISO 8601 string.
    • actor: Actor object.
    • action: String action type.
    • resource: Resource object.
    • metadata: Frozen dict.
    • hash: SHA-256 hash of event content. Ensures integrity.

    Actor¶

    Represents entity performing action.

    File: simple_audit/models.py

    Fields:

    • id: String identifier.
    • type: String (e.g., "user", "system", "service").
    • name: Optional display name.

    Resource¶

    Represents entity being acted upon.

    File: simple_audit/models.py

    Fields:

    • id: String identifier.
    • type: String (e.g., "document", "account").
    • version: Optional version number.

    Storage Backends¶

    StorageBackend abstract class defines interface.

    File: simple_audit/storage.py

    Methods:

    • save(event: AuditEvent) -> None
    • fetch(filters: dict, limit: int) -> list[AuditEvent]

    Default Implementation: InMemoryStorage

    • Stores events in list.

    Usage Examples¶

    Basic Logging¶

    from simple_audit import AuditLogger, Actor, Resource

# Initialize logger
logger = AuditLogger(actor=Actor(id="user-123", type="user", name="Alice"))

# Log an event
resource = Resource(id="doc-456", type="document")
event = logger.log(action="create", resource=resource, metadata={"title": "Q3 Report"})

print(event.id)
print(event.timestamp)

    Querying Events¶

    # Get all "delete" actions
deletions = logger.query(filter={"action": "delete"}, limit=10)

for e in deletions:
    print(f"{e.timestamp} - {e.actor.name} deleted {e.resource.id}")

    Custom Actor Per Event¶

    # Override default actor for specific action
system_actor = Actor(id="sys-001", type="system")
logger.log(action="cleanup", resource=Resource(id="temp-1", type="file"), actor=system_actor)

    Configuration¶

    No global configuration file. Configuration occurs via constructor arguments.

    • Storage: Pass StorageBackend instance to AuditLogger.
    • Default Actor: Pass Actor instance to AuditLogger.
    • Hashing: SHA-256 hardcoded in utils.py. Change requires modifying utils.py.

    Error Handling¶

    • StorageError: Raised if backend fails to save or fetch.
    • ValidationError: Raised if AuditEvent fields missing or invalid.

    Library does not retry failed storage operations. Application handles exceptions.

    Performance Considerations¶

    • In-Memory: O(1) save, O(n) fetch. Fast for small datasets.
    • Database Backends: Depends on backend. Index action and timestamp fields for query performance.
    • Hashing: SHA-256 computation adds negligible overhead.

    Integration Patterns¶

    1. Middleware: Wrap HTTP handlers to log requests/responses.
    2. Decorator: Apply @audit decorator to business logic functions.
    3. Explicit Calls: Manually call logger.log() after state changes.

    Decorator Example:

    from simple_audit.decorators import audit

@audit(action="update", resource_type="account")
def update_account(account_id: str, new_balance: float):
    # Business logic
    pass

    Note: decorators.py module provides audit decorator. Not shown in core module list but available for convenience.

    Security Notes¶

    • Hash Chain: Each event hash includes previous event hash. Detects tampering.
    • Actor Identity: Application responsible for authenticating actor. Library trusts provided Actor object.
    • Metadata: Do not store sensitive data (passwords, tokens) in metadata.

    Limitations¶

    • No built-in retention policy. Application must implement cleanup.
    • No real-time streaming. Polling required for live monitoring.
    • Single-node focus. Distributed tracing requires external tooling.

    Next Steps¶

    • Implement custom StorageBackend for production persistence.
    • Integrate with monitoring tools via query interface.
    • Review models.py for extending Actor or Resource fields.
