Results and Analysis

The simpleaudit library provides a robust framework for executing audit checks and analyzing the resulting data. This section details how to interpret the output structures generated by audit runs, how to aggregate results from repeated executions, and how to programmatically analyze audit findings.

Understanding the Result Structure

When an audit is executed, simpleaudit returns a structured object that encapsulates the status, details, and metadata of the check. The primary object returned is typically a Result instance (or a dictionary-like structure depending on the specific API version used).

Core Attributes

The result object contains the following key attributes:

Attribute Type Description
status str The final state of the audit check. Common values include "PASS", "FAIL", "WARN", and "ERROR".
message str A human-readable summary of the result. For failures, this often includes specific details about what went wrong.
timestamp datetime The exact time the audit check was executed.
duration float The time taken to execute the check, in seconds.
metadata dict Additional context-specific data provided by the specific audit plugin.

Example: Inspecting a Single Result

from simpleaudit import AuditRunner

# Initialize the runner
runner = AuditRunner()

# Execute a specific audit check
result = runner.run_check("check_file_permissions", target="/etc/passwd")

# Inspect the result
print(f"Status: {result.status}")
print(f"Message: {result.message}")
print(f"Duration: {result.duration:.4f}s")

if result.status == "FAIL":
    print(f"Details: {result.metadata.get('details', 'No details provided')}")

Aggregating Repeated Runs

In production environments, audits are often run repeatedly to monitor consistency or to detect transient issues. simpleaudit supports aggregating results over time to provide a holistic view of system health.

The Aggregator Class

The Aggregator class is responsible for collecting multiple Result objects and computing statistical summaries. It allows you to track trends, calculate pass rates, and identify flaky checks.

Key Methods:

  • add_result(result): Adds a single Result object to the aggregation buffer.
  • get_summary(): Returns a dictionary containing aggregated statistics.
  • get_history(check_name): Returns a list of results for a specific check name, ordered by timestamp.

Example: Aggregating Results

from simpleaudit import AuditRunner, Aggregator

runner = AuditRunner()
aggregator = Aggregator()

# Simulate multiple runs
for i in range(5):
    result = runner.run_check("check_disk_space", target="/var")
    aggregator.add_result(result)

# Get the aggregated summary
summary = aggregator.get_summary()

print(f"Total Checks: {summary['total_checks']}")
print(f"Pass Rate: {summary['pass_rate']:.2%}")
print(f"Average Duration: {summary['avg_duration']:.4f}s")

# Identify flaky checks (checks that have failed at least once but also passed)
flaky_checks = aggregator.get_flaky_checks()
for check_name in flaky_checks:
    print(f"Flaky Check: {check_name}")

Interpreting Audit Outputs

Interpreting audit outputs involves more than just checking the status field. Developers should leverage the metadata field and the message attribute to gain deeper insights into the system's state.

Status Codes

  • PASS: The check completed successfully, and the system meets the expected criteria.
  • FAIL: The check completed, but the system does not meet the expected criteria. The message field will contain specific failure reasons.
  • WARN: The check completed, but the system is in a suboptimal state that may require attention. This is often used for soft limits or recommendations.
  • ERROR: The check could not be completed due to an internal error, permission issue, or missing dependency. This status indicates a problem with the audit tool itself or the environment, not necessarily the audited system.

Handling Errors

When a check returns an ERROR status, it is critical to inspect the message and metadata fields to diagnose the issue.

result = runner.run_check("check_network_connectivity", target="example.com")

if result.status == "ERROR":
    error_msg = result.message
    error_code = result.metadata.get("error_code")

    if error_code == "TIMEOUT":
        print("Network check timed out. Verify connectivity.")
    elif error_code == "DNS_FAILURE":
        print("DNS resolution failed. Check DNS settings.")
    else:
        print(f"Unknown error: {error_msg}")

Programmatic Analysis

For advanced use cases, you may need to perform custom analysis on the audit results. simpleaudit provides a Analyzer class that offers utility methods for filtering, sorting, and transforming result data.

Filtering Results

You can filter results based on status, check name, or time range.

from simpleaudit import Analyzer

analyzer = Analyzer()

# Add results to the analyzer
for result in results_list:
    analyzer.add(result)

# Filter for all failed checks
failed_checks = analyzer.filter_by_status("FAIL")

# Filter for checks that took longer than 1 second
slow_checks = analyzer.filter_by_duration(min_duration=1.0)

# Sort results by duration (slowest first)
sorted_results = analyzer.sort_by_duration(descending=True)

Generating Reports

The Analyzer class can also generate simple text or JSON reports, which can be useful for logging or integration with other systems.

# Generate a JSON report
json_report = analyzer.generate_report(format="json")
print(json_report)

# Generate a text summary
text_summary = analyzer.generate_report(format="text")
print(text_summary)

Best Practices

  1. Always Check for Errors: Before interpreting PASS or FAIL statuses, ensure the result is not an ERROR. An ERROR status means the audit could not be performed, and the result is not indicative of the system's health.
  2. Use Metadata for Context: The metadata field often contains valuable context, such as specific file paths, error codes, or configuration values. Use this data to provide more actionable insights.
  3. Aggregate Over Time: Single audit runs can be noisy. Use the Aggregator class to collect results over time to identify trends and flaky checks.
  4. Log All Results: Store all Result objects in a persistent store (e.g., a database or log file) to enable historical analysis and reporting.

Conclusion

The simpleaudit library provides a comprehensive set of tools for executing and analyzing audit checks. By understanding the result structure, using the Aggregator and Analyzer classes, and following best practices for error handling, developers can build robust and insightful audit systems.
