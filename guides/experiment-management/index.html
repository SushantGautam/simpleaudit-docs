    Experiment management

    Experiment Management¶

    Experiment Management subsystem defines, executes, and tracks audit experiments. Experiment class core entity. Manages configuration, execution state, results.

    Core Classes¶

    Experiment¶

    Primary class representing single audit experiment.

    Parameters:

    Parameter Type Description
    name str Unique identifier for experiment.
    config dict Configuration dictionary. Contains audit parameters.
    data_source DataSource Source object providing audit data.
    metrics list[Metric] List of metric objects to compute.
    seed int Random seed for reproducibility. Default None.

    Attributes:

    • id: Unique experiment ID. Auto-generated.
    • status: Current status. Values: pending, running, completed, failed.
    • results: Dictionary of computed metrics.
    • created_at: Timestamp creation.
    • completed_at: Timestamp completion.

    Methods:

    • run(): Executes experiment. Returns ExperimentResult object.
    • validate(): Checks configuration validity. Raises ConfigError if invalid.
    • to_dict(): Serializes experiment to dictionary.
    • from_dict(data): Class method. Reconstructs experiment from dictionary.

    ExperimentManager¶

    Manages collection of experiments. Handles persistence, querying, lifecycle.

    Parameters:

    Parameter Type Description
    storage StorageBackend Backend for persisting experiment data. Default LocalFileStorage.

    Methods:

    • create_experiment(config): Creates new Experiment instance. Returns instance.
    • get_experiment(exp_id): Retrieves experiment by ID.
    • list_experiments(status=None): Lists experiments. Optional filter by status.
    • run_experiment(exp_id): Executes specific experiment.
    • delete_experiment(exp_id): Removes experiment record.

    Configuration¶

    Experiments define behavior via config dictionary.

    Standard Keys:

    • audit_type: String. Type of audit. E.g., consistency, completeness.
    • sample_size: Integer. Number of records to audit. None means full dataset.
    • threshold: Float. Acceptable error rate. Default 0.0.
    • timeout: Integer. Execution timeout seconds. Default 300.
    • parallel_workers: Integer. Number of parallel workers. Default 1.

    Example Config:

    config = {
    "audit_type": "consistency",
    "sample_size": 1000,
    "threshold": 0.05,
    "timeout": 60,
    "parallel_workers": 4
}

    Usage Examples¶

    Creating and Running Experiment¶

    from simpleaudit import Experiment, ExperimentManager, LocalFileStorage
from simpleaudit.data import CSVDataSource
from simpleaudit.metrics import ErrorRate, CompletenessScore

# Setup
storage = LocalFileStorage(path="./experiments")
manager = ExperimentManager(storage=storage)

# Define data source
source = CSVDataSource(file_path="data.csv")

# Define metrics
metrics = [
    ErrorRate(name="error_rate"),
    CompletenessScore(name="completeness")
]

# Create experiment
exp = Experiment(
    name="test_consistency_01",
    config={
        "audit_type": "consistency",
        "sample_size": 500,
        "threshold": 0.01
    },
    data_source=source,
    metrics=metrics,
    seed=42
)

# Validate
exp.validate()

# Run
result = exp.run()

# Access results
print(result.metrics)
print(result.status)

    Managing Multiple Experiments¶

    # Create via manager
exp_id = manager.create_experiment(
    name="bulk_test",
    config={"audit_type": "completeness", "sample_size": 100},
    data_source=source,
    metrics=metrics
)

# Run via manager
manager.run_experiment(exp_id)

# List all completed experiments
completed = manager.list_experiments(status="completed")
for e in completed:
    print(e.name, e.results)

    Reproducibility¶

    Set seed parameter to ensure identical results across runs.

    exp1 = Experiment(name="run_1", config=config, data_source=source, metrics=metrics, seed=123)
exp2 = Experiment(name="run_2", config=config, data_source=source, metrics=metrics, seed=123)

result1 = exp1.run()
result2 = exp2.run()

assert result1.metrics == result2.metrics

    Error Handling¶

    • ConfigError: Raised by validate() or run() if config invalid.
    • DataSourceError: Raised if data source fails to load.
    • TimeoutError: Raised if execution exceeds timeout.

    Catch specific exceptions to handle failures gracefully.

    try:
    exp.run()
except ConfigError as e:
    print(f"Invalid config: {e}")
except TimeoutError:
    print("Audit timed out")

    Persistence¶

    ExperimentManager persists experiment metadata and results.

    • LocalFileStorage: Saves JSON files to local directory.
    • DatabaseStorage: Saves to SQL database. Requires connection string.

    Serialization uses to_dict() and from_dict(). Ensures state preservation across sessions.

    Best Practices¶

    1. Unique Names: Use descriptive, unique names. Avoid collisions.
    2. Seed Setting: Always set seed for reproducible audits.
    3. Validation: Call validate() before run() to catch config errors early.
    4. Sampling: Use sample_size for large datasets. Speeds up execution.
    5. Parallelism: Increase parallel_workers for CPU-bound audits.

    File Structure¶

    • simpleaudit/experiment.py: Contains Experiment class.
    • simpleaudit/manager.py: Contains ExperimentManager class.
    • simpleaudit/storage.py: Contains storage backends.

    This module enables systematic tracking of audit runs. Facilitates comparison of results across different configurations or data states.
