    Results analysis

    Results & Analysis¶

    SimpleAudit processes, stores, and interprets audit results. Subsystem aggregates LLM judge scores across models and scenario packs. Enables comparison, visualization, statistical analysis.

    Overview¶

    Audit execution generates raw judge outputs. Results module handles:

    1. Normalization: Convert raw judge responses to standardized scores.
    2. Aggregation: Compute mean, median, min, max per scenario/model.
    3. Storage: Persist results to JSON/CSV files.
    4. Comparison: Calculate deltas between models or judges.
    5. Visualization: Generate browser-ready HTML reports.

    Core classes: AuditResult, ResultAggregator, ComparisonEngine.

    Core Classes¶

    AuditResult¶

    Represents single audit outcome. Immutable data structure.

    class AuditResult:
    def __init__(self, model_id: str, scenario_id: str, judge_id: str, 
                 scores: Dict[str, float], raw_response: str, timestamp: float):
        self.model_id = model_id
        self.scenario_id = scenario_id
        self.judge_id = judge_id
        self.scores = scores  # Keys: "safety", "harm", "factuality", "helpfulness"
        self.raw_response = raw_response
        self.timestamp = timestamp

    Attributes:

    Attribute Type Description
    model_id str Identifier for evaluated model (e.g., "gpt-4", "llama-3").
    scenario_id str Identifier for test case from scenario pack.
    judge_id str Identifier for LLM judge used (e.g., "claude-3-opus").
    scores Dict[str, float] Normalized scores. Range 0.0-1.0. Keys fixed: safety, harm, factuality, helpfulness.
    raw_response str Original JSON/text from judge. Used for debugging.
    timestamp float Unix epoch time of evaluation.

    timestamp=1718000001

print(stats["gpt-4"]["mean"])  # Output: 0.925 (avg of safety scores, example)

    Configuration¶

    No global config file. Parameters passed directly to functions.

    Score Normalization: Judges may output 0-10 or 0-100 scales. AuditResult constructor expects 0.0-1.0. Pre-normalize before adding to aggregator.

    # If judge returns 0-10 scale
raw_score = 8.5
normalized = raw_score / 10.0

    Error Handling¶

    • Invalid Metric: ValueError if metric key not in {"safety", "harm", "factuality", "helpfulness"}.
    • Missing Model: KeyError if model_id not found in aggregator during comparison.
    • File Errors: IOError on save/load failures.

    Best Practices¶

    1. Batch Add: Use add_batch for large datasets. Reduces overhead.
    2. Filter Early: Apply filter() before aggregation to reduce computation.
    3. Save Frequently: Persist results after each scenario pack. Prevents data loss on crash.
    4. Raw Response: Always store raw_response. Essential for debugging judge failures.
    5. Metric Selection: Use safety for compliance reports. Use helpfulness for UX evaluations.

    Summary¶

    Results module transforms raw LLM outputs into actionable insights. Key workflow:

    1. Create AuditResult objects from judge outputs.
    2. Accumulate in ResultAggregator.
    3. Compute stats via get_statistics().
    4. Compare models via ComparisonEngine.
    5. Persist with save_results().
    6. Visualize with generate_report().

    All operations deterministic. No external dependencies beyond standard library and json.
