    Experiments & Results¶

    SimpleAudit experiments module manages experiment lifecycle. Defines Experiment class. Handles output processing. Aggregates repeated runs. Ensures reproducibility. Tracks metadata.

    Overview¶

    Experiment object encapsulates audit run. Stores configuration. Records results. Manages file I/O. Supports batch processing. Aggregation logic combines multiple runs. Useful for statistical analysis. Reduces noise. Identifies consistent failures.

    Experiment Class¶

    Primary container. Represents single audit execution.

    Constructor¶

    class Experiment:
    def __init__(self, name: str, config: dict, output_dir: str = "./experiments"):
        """
        Initialize experiment.

        Args:
            name: Unique identifier. String.
            config: Audit configuration. Dict. Contains target, rules, options.
            output_dir: Base directory for artifacts. String. Defaults "./experiments".
        """

    Attributes:

    Attribute Type Description
    name str Experiment ID.
    config dict Immutable config snapshot.
    output_dir str Path to results folder.
    results list List of Result objects.
    metadata dict Timestamps, version, environment info.

    Result Class¶

    Represents single audit check outcome.

    Constructor¶

    class Result:
    def __init__(self, rule_id: str, status: str, message: str, details: dict = None):
        """
        Args:
            rule_id: Identifier for audit rule.
            status: "pass", "fail", "warn", "error".
            message: Human-readable description.
            details: Optional dict with extra data.
        """

    Attributes:

    Attribute Type Description
    rule_id str Rule identifier.
    status str Outcome status.
    message str Description.
    details dict Context data.
    timestamp datetime Execution time.

    Aggregation¶

    aggregate_experiments function combines multiple runs. Useful for stability testing.

    def aggregate_experiments(experiments: list[Experiment], threshold: float = 0.8) -> dict:
    """
    Aggregate results from multiple experiments.

    Args:
        experiments: List of Experiment objects.
        threshold: Minimum consistency ratio. Float 0.0-1.0.

    Returns:
        Dict with aggregated stats.
        Keys:
            - "total_runs": int
            - "consistent_rules": list[str]
            - "flaky_rules": list[str]
            - "failure_rate": float
    """

    Logic: 1. Collect all Result objects. 2. Group by rule_id. 3. Calculate pass rate per rule. 4. Mark rule "consistent" if pass rate >= threshold. 5. Mark rule "flaky" if pass rate < threshold and > 0. 6. Mark rule "failing" if pass rate == 0.

    Code Examples¶

    Basic Usage¶

    from simpleaudit.experiments import Experiment

# Define config
config = {
    "target": "./my_project",
    "rules": ["security", "performance"],
    "options": {"verbose": True}
}

# Create experiment
exp = Experiment(name="test_run_01", config=config)

# Execute
exp.run()

# View summary
print(exp.summary())

# Save results
path = exp.save()
print(f"Saved to {path}")

    Aggregating Multiple Runs¶

    from simpleaudit.experiments import Experiment, aggregate_experiments

# Run same config 5 times
experiments = []
for i in range(5):
    exp = Experiment(name=f"run_{i}", config=config)
    exp.run()
    experiments.append(exp)

# Aggregate
stats = aggregate_experiments(experiments, threshold=0.9)

print(f"Total runs: {stats['total_runs']}")
print(f"Flaky rules: {stats['flaky_rules']}")
print(f"Failure rate: {stats['failure_rate']:.2%}")

    Loading Saved Experiment¶

    from simpleaudit.experiments import Experiment

# Restore from disk
exp = Experiment.load("./experiments/test_run_01/experiment.json")

# Access results
for result in exp.results:
    if result.status == "fail":
        print(f"Failed: {result.rule_id} - {result.message}")

    Configuration Options¶

    config dict supports:

    Key Type Required Description
    target str Yes Path to codebase.
    rules list[str] Yes List of rule IDs.
    options dict No Rule-specific settings.
    timeout int No Max seconds per rule. Default 30.
    parallel bool No Enable parallel execution. Default False.

    File Structure¶

    Experiment creates directory structure:

    ./experiments/
└── test_run_01/
    ├── experiment.json      # Serialized state
    ├── raw_output.log       # Raw stdout/stderr
    └── results/
        ├── security.json    # Rule-specific results
        └── performance.json

    Best Practices¶

    1. Unique Names: Use timestamp or UUID for name. Prevents overwrites.
    2. Version Control: Commit config files. Track changes.
    3. Aggregation: Run 3-5 times for flaky detection. Single run insufficient.
    4. Cleanup: Delete old experiments. Disk space grows fast.
    5. Logging: Enable verbose in options for debugging.

    Error Handling¶

    Exceptions raised:

    Exception Cause
    ConfigError Invalid config dict. Missing keys.
    FileNotFoundError Target path missing.
    TimeoutError Rule execution exceeds limit.
    SerializationError Invalid JSON structure.

    Catch specific exceptions:

    from simpleaudit.exceptions import ConfigError, TimeoutError

try:
    exp.run()
except ConfigError as e:
    print(f"Config issue: {e}")
except TimeoutError as e:
    print(f"Timeout: {e}")

    Integration¶

    Experiment integrates with simpleaudit.core. Uses AuditEngine internally. Does not expose engine directly. Abstracts complexity.

    For advanced use, access exp._engine (private). Not recommended. May break in future versions.

    Limitations¶

    • No distributed execution. Single machine only.
    • No real-time streaming. Batch processing only.
    • JSON serialization. Large results may be slow.
    • No encryption. Sensitive data in plain text.
