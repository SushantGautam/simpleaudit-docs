Getting started

Getting Started

Welcome to simpleaudit. This library provides a streamlined interface for executing local, privacy-preserving code audits using Large Language Models (LLMs). Unlike cloud-based audit services, simpleaudit allows you to run inference entirely on your local machine, ensuring that your proprietary code never leaves your infrastructure.

This guide covers the installation process, environment configuration, and how to execute your first audit using a local model.

Prerequisites

Before installing simpleaudit, ensure your development environment meets the following requirements:

  1. Python Version: Python 3.8 or higher is required.
  2. Hardware: Since the library relies on local LLM inference, a GPU with sufficient VRAM (recommended: 8GB+ for 7B parameter models) is highly recommended for reasonable performance. CPU-only inference is supported but significantly slower.
  3. Dependencies:
    • torch: PyTorch must be installed. Ensure you install the version compatible with your CUDA setup (if using a GPU).
    • transformers: The Hugging Face transformers library is required for model loading.
    • accelerate: Optional but recommended for multi-GPU setups or memory optimization.

Installation

You can install simpleaudit via pip. It is recommended to use a virtual environment to manage dependencies.

# Create and activate a virtual environment
python -m venv venv
source venv/bin/activate  # On Windows use `venv\Scripts\activate`

# Install the library
pip install simpleaudit

If you are using a GPU, ensure your PyTorch installation supports CUDA. If pip install simpleaudit does not pull the correct GPU-enabled PyTorch, you may need to install PyTorch separately first:

# Example for CUDA 11.8
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu118

# Then install simpleaudit
pip install simpleaudit

Environment Setup

simpleaudit utilizes the Hugging Face ecosystem to download and cache models. You do not need to manually download model weights; the library handles this automatically on the first run.

Model Selection

The library supports any model compatible with the transformers AutoModelForCausalLM interface. Common choices for code auditing include:

  • codellama/CodeLlama-7b-hf
  • meta-llama/Llama-2-7b-chat-hf
  • mistralai/Mistral-7B-v0.1

Note: Some models (like Llama 2) require you to accept the license agreement on the Hugging Face Hub before downloading. You can do this by visiting the model page on Hugging Face and clicking "Agree and continue".

Configuration

The core configuration is handled via the AuditConfig dataclass. This allows you to specify the model name, device mapping, and generation parameters.

Running Your First Audit

The primary entry point for simpleaudit is the SimpleAuditor class. Below is a step-by-step guide to running an audit on a Python file.

1. Initialize the Auditor

First, import the necessary classes and instantiate the SimpleAuditor. You must provide a model_name string corresponding to a Hugging Face model ID.

from simpleaudit import SimpleAuditor, AuditConfig

# Define configuration
config = AuditConfig(
    model_name="codellama/CodeLlama-7b-hf",
    device_map="auto",  # Automatically places model on available GPU/CPU
    max_new_tokens=512, # Maximum length of the audit response
    temperature=0.2     # Low temperature for more deterministic, factual output
)

# Initialize the auditor
# This will download the model if not already cached
auditor = SimpleAuditor(config)

2. Prepare the Code for Audit

The auditor expects the source code as a string. You can read this from a file or pass it directly.

# Example: Reading a file
with open("example_script.py", "r") as f:
    code_to_audit = f.read()

3. Execute the Audit

Call the audit method on the SimpleAuditor instance. This method returns an AuditResult object containing the generated text and metadata.

# Run the audit
result = auditor.audit(code_to_audit)

# Print the audit report
print(result.text)

Full Example

Here is a complete, runnable script demonstrating the workflow:

import os
from simpleaudit import SimpleAuditor, AuditConfig

def main():
    # 1. Configure the auditor
    # Using a smaller model for this example to ensure faster loading
    # In production, use a larger model for better accuracy
    config = AuditConfig(
        model_name="codellama/CodeLlama-7b-hf",
        device_map="auto",
        max_new_tokens=1024,
        top_p=0.9,
        repetition_penalty=1.1
    )

    # 2. Initialize
    print("Loading model...")
    auditor = SimpleAuditor(config)
    print("Model loaded.")

    # 3. Define code to audit
    sample_code = """
def calculate_average(numbers):
    if not numbers:
        return 0
    total = 0
    for num in numbers:
        total += num
    return total / len(numbers)
"""

    # 4. Run audit
    print("Running audit...")
    result = auditor.audit(sample_code)

    # 5. Output results
    print("\n--- Audit Report ---")
    print(result.text)
    print("---------------------")

    # 6. Optional: Save to file
    with open("audit_report.txt", "w") as f:
        f.write(result.text)

if __name__ == "__main__":
    main()

API Reference

SimpleAuditor

The main class for interacting with the local model.

Constructor:

SimpleAuditor(config: AuditConfig)
  • config: An instance of AuditConfig containing model and generation parameters.

Methods:

  • audit(code: str) -> AuditResult
    • Description: Processes the input code string and generates an audit report.
    • Parameters:
      • code (str): The source code to be analyzed.
    • Returns:
      • AuditResult: An object containing the generated text (text) and optional metadata.

AuditConfig

A dataclass for defining the behavior of the auditor.

Attributes:

Attribute Type Default Description
model_name str Required The Hugging Face model ID (e.g., "codellama/CodeLlama-7b-hf").
device_map str "auto" Strategy for mapping model layers to devices. Use "auto" for automatic GPU/CPU distribution.
max_new_tokens int 512 The maximum number of tokens to generate in the response.
temperature float 0.2 Sampling temperature. Lower values make the output more deterministic.
top_p float 0.9 Nucleus sampling parameter.
repetition_penalty float 1.1 Penalty applied to repeated tokens to prevent loops.

AuditResult

The object returned by the audit method.

Attributes:

  • text (str): The full text of the audit report generated by the LLM.
  • model_name (str): The name of the model used for the audit.
  • duration (float): The time in seconds the inference took.

Best Practices

  1. Model Caching: The first run will download the model weights, which can be several gigabytes. Subsequent runs will load from the local cache (~/.cache/huggingface), which is much faster.
  2. Prompt Engineering: While simpleaudit uses a default system prompt optimized for code auditing, you can potentially customize this by modifying the internal prompt template if you have specific audit criteria (e.g., focusing only on SQL injection or memory leaks).
  3. Resource Management: If you are running multiple audits in a loop, consider keeping the SimpleAuditor instance alive rather than re-initializing it for each file, as loading the model into memory is the most expensive operation.
  4. GPU Memory: If you encounter CUDA out of memory errors, try reducing the max_new_tokens or using a smaller model variant (e.g., 7b instead of 13b).

Troubleshooting

  • Model Download Errors: Ensure you have accepted the license for gated models on Hugging Face. Check your internet connection.
  • Slow Inference: Verify that PyTorch is using your GPU. You can check this by running import torch; print(torch.cuda.is_available()). If it returns False, your PyTorch installation may be CPU-only.
  • Garbage Output: If the model generates nonsensical text, try lowering the temperature to 0.1 or ensuring the model is fully loaded before calling audit.

By following this guide, you should now be able to integrate simpleaudit into your CI/CD pipeline or development workflow to automate code quality checks locally.
