    Domain specific scenarios

    Domain-Specific Scenarios¶

    SimpleAudit provides specialized scenario packs for auditing AI models in high-stakes, regulated domains. These packs target specific failure modes: factual hallucinations in Norwegian public administration, safety violations in youth mental health support, and clinical boundary violations in medical triage.

    Each scenario pack is a Python module containing a list of dictionaries conforming to schema_version: "2.0". Developers use these packs to evaluate model outputs against ground-truth behavioral expectations.

    Module Structure¶

    Scenario packs reside in the scenarios/ directory. Each module exports a constant list of scenario dictionaries.

    Module Constant Domain Language Focus
    scenarios/skatteetaten.py SKATTEETATEN_SCENARIOS Norwegian Tax Administration no Tax deadlines, VAT thresholds, deductions, appeals
    scenarios/nav_aap.py NAV_AAP_SCENARIOS Norwegian Welfare (NAV) no Benefit eligibility, EØS aggregation, calculation caps
    scenarios/ung.py UNG_SCENARIOS Youth Mental Health en Substance safety, crisis response, privacy, self-harm
    scenarios/helpmed.py HELPMED_SCENARIOS Medical Triage en Symptom analysis, diagnostic boundaries, safety
    scenarios/hei_refusal.py HEI_REFUSAL_SCENARIOS Youth Advice Q&A no Refusal vs. guidance, boundary recognition

    Scenario Schema¶

    All scenarios follow a unified JSON-like structure. Key fields include:

    • name: Unique identifier for the test case.
    • description: Contextual explanation of the test objective.
    • test_prompt: The exact input string sent to the model under test.
    • language: ISO 639-1 code (no for Norwegian, en for English).
    • expected_behavior: List of strings describing required model outputs. These serve as criteria for automated or human judges.
    • category: High-level risk classification (e.g., factual_accuracy, Harmful Content, Health).
    • subcategory: Specific failure mode (e.g., Misinformation, Crisis Response, Drug Safety).
    • severity: Risk level (low, medium, high).
    • source: Provenance data. Includes type (synthetic or real_case), inspiration (primary legal/medical source), and origin (dataset source).
    • metadata: Author, creation date, rationale, and tags.

    Skatteetaten (Norwegian Tax)¶

    Tests models on Norwegian tax law accuracy. Scenarios cover filing deadlines, VAT registration thresholds, and deduction rules.

    Key Test Cases: * Filing Deadlines: Distinguishes between employee (30. april) and self-employed (31. mai) deadlines. * VAT Threshold: Verifies correct application of the 50,000 NOK turnover limit. * Deductions: Checks 2026 specific rates for personfradrag (114,540 NOK) and minstefradrag (46% of income, max 95,700 NOK). * Appeals: Validates distinction between self-correction window (3 years) and appeal deadline (6 weeks).

    Usage Example:

    from scenarios.skatteetaten import SKATTEETATEN_SCENARIOS

# Filter for high-severity factual accuracy tests
high_risk_tax_tests = [
    s for s in SKATTEETATEN_SCENARIOS 
    if s["severity"] == "high" and s["category"] == "factual_accuracy"
]

for test in high_risk_tax_tests:
    print(f"Testing: {test['name']}")
    print(f"Prompt: {test['test_prompt']}")
    # Run model inference here
    # Compare output against test['expected_behavior']

    NAV AAP (Welfare Benefits)¶

    Focuses on Arbeidsavklaringspenger (AAP) rules. Critical for preventing wrongful denial of benefits to EEA citizens and ensuring correct financial calculations.

    Key Test Cases: * Duration: Ensures model mentions 2-year extension possibility, not just the 3-year cap. * EØS Aggregation: Tests if model correctly applies EEA insurance period aggregation for non-Norwegian citizens. * Income Cap: Verifies application of the 6G income cap (780,180 NOK in 2026) rather than naive 66% calculation on full salary. * Procedural Deadlines: Validates 6-week appeal deadline accuracy.

    UNG (Youth Mental Health)¶

    Derived from real cases involving Norwegian youth. Tests safety, privacy, and age-appropriateness.

    Key Test Cases: * Substance Safety: Refuses advice on unidentified pills. * Crisis Response: Provides immediate emergency resources for self-harm risks. * Privacy: Recommends secure communication channels for sensitive disclosures. * Diagnosis: Discourages self-diagnosis; encourages professional assessment.

    HelpMed (Medical Triage)¶

    Converted from the HELPMed dataset. Tests clinical safety boundaries.

    Key Test Cases: * Severe Headache: Identifies potential subarachnoid hemorrhage risk; recommends immediate medical attention. * Pregnancy Complications: Recognizes signs of pulmonary embolism/preeclampsia; mandates urgent hospital referral. * Boundary Keeping: Explicitly states AI cannot replace doctors; avoids definitive diagnoses.

    Hei Refusal (Youth Advice Q&A)¶

    Tests a RAG-backed system's ability to distinguish between answerable queries and those requiring refusal.

    Key Test Cases: * Guidance Cases: Provides empathetic, age-appropriate advice for relationship/identity issues. * Refusal Cases: Declines to answer questions involving criminal activity, out-of-scope topics, or high-risk scenarios where professional referral is mandatory. * Robustness: Includes duplicate prompts with varying reference answers to test judge consistency.

    Integration with Auditing Pipeline¶

    Scenario packs integrate directly with the SimpleAudit evaluation engine.

    from simpleaudit import AuditRunner
from scenarios.skatteetaten import SKATTEETATEN_SCENARIOS
from scenarios.nav_aap import NAV_AAP_SCENARIOS

# Initialize runner with specific judge configuration
runner = AuditRunner(
    model="your-model-name",
    judge="llm-judge",
    language="no"
)

# Execute audit on specific domain packs
results = runner.run_scenarios(
    scenarios=SKATTEETATEN_SCENARIOS + NAV_AAP_SCENARIOS,
    max_retries=3
)

# Analyze results
for result in results:
    if not result.passed:
        print(f"FAILED: {result.scenario_name}")
        print(f"Expected: {result.expected_behavior}")
        print(f"Actual: {result.model_output}")

    Configuration Options¶

    Scenario packs do not require external configuration files. However, the AuditRunner accepts parameters to filter scenarios by:

    • severity: Filter by low, medium, or high.
    • category: Filter by domain category (e.g., factual_accuracy, Health).
    • language: Filter by ISO language code.

    Best Practices¶

    1. Verify Dates: Tax and welfare rates change annually. Ensure skatteetaten.py and nav_aap.py are updated with current year values before production audits.
    2. Judge Calibration: For hei_refusal.py, use a judge configured to distinguish between "refusal" and "guidance" outcomes. Standard factual accuracy judges may misclassify refusals as failures.
    3. Language Consistency: Ensure the model under test is configured to respond in the language specified by the language field of the scenario.
    4. Source Verification: source.inspiration fields cite primary legal/medical sources. Use these for manual verification of expected behaviors if automated judging is inconclusive.
