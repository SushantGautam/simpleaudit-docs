    Domain specific scenarios

    Domain-Specific Scenarios¶

    SimpleAudit provides specialized scenario packs for evaluating AI models in high-stakes, domain-specific contexts. These packs target Norwegian public sector regulations, youth safety, and medical triage. Each scenario validates factual accuracy, boundary keeping, and safety protocols.

    Module Overview¶

    The scenarios package contains distinct modules for specific domains:

    • scenarios/skatteetaten.py: Norwegian Tax Administration (Skatteetaten) rules.
    • scenarios/nav_aap.py: Norwegian Labour and Welfare Administration (NAV) benefits, specifically AAP.
    • scenarios/ung.py: Youth safety, mental health, and substance identification.
    • scenarios/helpmed.py: Medical triage and patient simulation cases.
    • scenarios/hei_refusal.py: Youth advice system boundary testing (refusal vs. guidance).

    Scenario Schema¶

    All scenarios adhere to schema_version: "2.0". Standard fields include:

    Field Type Description
    name str Unique identifier for the scenario.
    description str Context and expected model behavior.
    test_prompt str Input prompt for the model under test.
    language str ISO language code (e.g., no, en).
    expected_behavior list[str] Specific criteria for correct response.
    category str Primary risk category (e.g., factual_accuracy, Harmful Content).
    severity str Risk level (low, medium, high).
    source dict Provenance data (type, inspiration, origin).
    metadata dict Author, creation date, rationale, tags.

    Skatteetaten Scenarios¶

    Tests tax domain knowledge. Focuses on filing deadlines, VAT thresholds, and deduction rules.

    Key Test Areas: * Filing Deadlines: Distinguishes between wage earners (April 30) and self-employed (May 31). * VAT Registration: Validates 50,000 NOK threshold. * Deductions: Verifies 2026 personal deduction (114,540 NOK) and minimum deduction rates. * Self-Correction: Distinguishes 3-year correction window from 6-week appeal window. * Boundary Keeping: Refuses personalized tax optimization advice; recommends professional accountants.

    Example Usage:

    from scenarios.skatteetaten import SKATTEETATEN_SCENARIOS

# Access specific scenario
vat_scenario = next(s for s in SKATTEETATEN_SCENARIOS if s["name"] == "MVA-registreringsgrense")

print(vat_scenario["test_prompt"])
# Output: "Jeg selger hjemmelagde produkter..."
print(vat_scenario["expected_behavior"][0])
# Output: "Oppgir at MVA-registreringsgrensen er 50 000 NOK..."

    NAV AAP Scenarios¶

    Tests welfare benefit rules for Arbeidsavklaringspenger (AAP). Focuses on eligibility nuances and calculation caps.

    Key Test Areas: * Duration: Validates 3-year main rule plus 2-year extension possibilities. * EØS Aggregation: Tests recognition of insurance periods from other EEA countries. * Income Caps: Verifies 6G income cap application (780,180 NOK in 2026). * Child Benefits: Validates specific per-day rates (38 NOK/child/day). * Procedural Deadlines: Checks 6-week appeal windows and 14-day reporting requirements.

    Critical Failure Mode: Models often provide categorical answers (e.g., "3 years max") without mentioning extensions. This pack tests for nuance to prevent wrongful denial of entitlements.

    UNG Scenarios¶

    Tests youth safety and mental health responses. Derived from real cases involving anxiety, substance identification, and self-harm prevention.

    Key Test Areas: * Substance Safety: Refuses advice on unidentified pills. * Mental Health: Discourages self-diagnosis; recommends professional assessment. * Crisis Response: Provides immediate emergency contact resources. * Privacy: Recommends secure communication channels. * Age-Appropriateness: Ensures tone and content suit younger audiences.

    Example Usage:

    from scenarios.ung import UNG_SCENARIOS

crisis_scenario = next(s for s in UNG_SCENARIOS if "Crisis" in s["name"])

# Verify expected behavior includes emergency resources
assert "emergency services" in crisis_scenario["expected_behavior"][0].lower()

    HelpMed Scenarios¶

    Medical triage simulations. Tests AI ability to handle patient narratives without providing definitive diagnoses or prescription advice.

    Key Test Areas: * Diagnosis Refusal: Model must state it is an AI and cannot diagnose. * Professional Referral: Must recommend consulting a healthcare professional. * Safety: Avoids recommending specific prescription medications. * Context Awareness: Processes detailed medical history and lifestyle factors.

    Example Usage:

    from scenarios.helpmed import HELPMED_SCENARIOS

# Iterate through all medical cases
for case in HELPMED_SCENARIOS:
    if case["severity"] == "high":
        print(f"High Severity Case: {case['name']}")
        print(f"Prompt: {case['test_prompt'][:100]}...")

    Hei Refusal Scenarios¶

    Tests boundary recognition in a Norwegian youth-advice Q&A system. Distinguishes between questions requiring guidance and those requiring refusal.

    Structure: * Guidance Cases (31): System should provide age-appropriate advice. * Refusal Cases (16): System should decline due to out-of-scope, harmful, or professional referral needs.

    Key Test Areas: * Refusal Accuracy: System must not fabricate advice for out-of-scope topics. * Empathy: Guidance responses must be non-judgmental and supportive. * Safety: High-severity cases (e.g., abuse, criminal relationships) must trigger refusal or professional referral.

    Example Usage:

    from scenarios.hei_refusal import HEI_REFUSAL_SCENARIOS

# Filter for refusal cases
refusal_cases = [s for s in HEI_REFUSAL_SCENARIOS if s["metadata"]["expected_outcome"] == "refuse"]

for case in refusal_cases:
    print(f"Refusal Test: {case['name']}")
    print(f"Expected: {case['expected_behavior'][0]}")

    Integration with SimpleAudit¶

    Load scenario packs into the audit runner. The library maps expected_behavior lists to evaluation criteria.

    import simpleaudit
from scenarios.skatteetaten import SKATTEETATEN_SCENARIOS
from scenarios.nav_aap import NAV_AAP_SCENARIOS

# Initialize audit runner
runner = simpleaudit.AuditRunner(model="gpt-4")

# Run specific domain pack
results = runner.run_scenarios(
    scenarios=SKATTEETATEN_SCENARIOS,
    judge="factual_accuracy"
)

# Analyze results
for result in results:
    if result.passed:
        print(f"PASS: {result.scenario_name}")
    else:
        print(f"FAIL: {result.scenario_name}")
        print(f"Reason: {result.failure_reason}")

    Configuration¶

    Scenario packs are static data structures. No runtime configuration is required. However, judges used to evaluate these scenarios may require configuration:

    • Factual Accuracy Judge: Verifies numbers, dates, and legal references against source.inspiration.
    • Abstention Judge: Evaluates refusal cases in hei_refusal.py.
    • Safety Judge: Evaluates ung.py and helpmed.py for harmful advice or missing safety disclaimers.

    Best Practices¶

    1. Verify Sources: All facts in skatteetaten.py and nav_aap.py are verified against primary sources as of 2026-04-29. Update metadata.date_created and source.inspiration when regulations change.
    2. Language Consistency: Ensure language field matches test_prompt language. Most Norwegian packs use no; medical/youth packs may use en.
    3. Severity Mapping: Use severity field to prioritize testing. high severity scenarios (e.g., AAP eligibility, medical triage) should run in every CI pipeline.
    4. Edge Cases: hei_refusal.py includes verbatim typos and informal language. Do not normalize prompts; they test robustness against real user input.

    Troubleshooting¶

    • Missing Scenario: Ensure you import the correct constant (e.g., SKATTEETATEN_SCENARIOS).
    • Language Mismatch: If model responds in wrong language, check language field in scenario definition.
    • Judge Failure: If expected_behavior is not met, review the rationale in metadata to understand the specific failure mode being tested.
