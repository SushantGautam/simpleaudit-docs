    Model auditing

    Model Auditing¶

    SimpleAudit provides robust mechanisms for evaluating model behavior across local and API-hosted environments. Module simpleaudit.model_audit handles audit configuration, execution, and result aggregation. Supports deterministic testing, statistical analysis, and compliance checks.

    Core Concepts¶

    Audits measure model output against defined criteria. Criteria include:

    • Accuracy: Correctness of factual claims.
    • Safety: Adherence to safety guidelines.
    • Consistency: Stability across multiple runs.
    • Latency: Response time metrics.

    System abstracts model interface. Developers define AuditConfig specifying model endpoint, input dataset, and evaluation metrics. Runner executes tests, collects results, generates reports.

    Key Classes¶

    AuditConfig¶

    Configuration object for audit execution.

    Parameter Type Description
    model_name str Identifier for model. Local path or API key.
    endpoint str URL for API-hosted models. Optional for local.
    dataset_path str Path to JSON/CSV input file.
    metrics List[str] List of active metrics. e.g., ["accuracy", "safety"].
    temperature float Sampling temperature. Default 0.0 for determinism.
    max_tokens int Maximum output tokens.
    concurrency int Parallel requests. Default 1.

    AuditRunner¶

    Executes audit pipeline.

    Methods:

    • run(config: AuditConfig) -> AuditReport: Initiates audit. Returns report object.
    • validate_config(config: AuditConfig) -> bool: Checks configuration validity.
    • load_dataset(path: str) -> List[dict]: Loads input data.

    AuditReport¶

    Container for results.

    Properties:

    • total_samples: Total inputs processed.
    • success_rate: Percentage of valid responses.
    • metric_scores: Dict mapping metric names to average scores.
    • failures: List of failed test cases.
    • duration_seconds: Total execution time.

    Configuration Options¶

    Local models require Hugging Face or custom loader setup. API models need valid credentials.

    Local Model Setup:

    from simpleaudit.config import AuditConfig
from simpleaudit.runner import AuditRunner

config = AuditConfig(
    model_name="local_model_path",
    dataset_path="data/test_set.json",
    metrics=["accuracy", "consistency"],
    temperature=0.0,
    max_tokens=128
)

    API Model Setup:

    config = AuditConfig(
    model_name="gpt-4",
    endpoint="https://api.openai.com/v1",
    api_key="sk-...",
    dataset_path="data/test_set.json",
    metrics=["safety", "latency"],
    concurrency=5
)

    Execution Workflow¶

    1. Initialize: Create AuditConfig instance.
    2. Validate: Call AuditRunner.validate_config(). Catches missing files, invalid endpoints.
    3. Run: Invoke AuditRunner.run().
    4. Analyze: Inspect AuditReport.

    Code Examples¶

    Basic Local Audit¶

    import simpleaudit as sa

# Define configuration
cfg = sa.AuditConfig(
    model_name="bert-base-uncased",
    dataset_path="samples/questions.json",
    metrics=["accuracy"]
)

# Execute audit
runner = sa.AuditRunner()
report = runner.run(cfg)

# Output results
print(f"Accuracy: {report.metric_scores['accuracy']:.2f}")
print(f"Samples: {report.total_samples}")

    API Audit with Concurrency¶

    cfg = sa.AuditConfig(
    model_name="claude-3-opus",
    endpoint="https://api.anthropic.com",
    api_key="ant-key-...",
    dataset_path="samples/safety_tests.json",
    metrics=["safety"],
    concurrency=10
)

runner = sa.AuditRunner()
report = runner.run(cfg)

# Log failures
for failure in report.failures:
    print(f"Failed: {failure.input_id} - {failure.reason}")

    Custom Metric Integration¶

    Developers can register custom metrics.

    from simpleaudit.metrics import register_metric

@register_metric("custom_relevance")
def relevance_score(input_text, output_text):
    # Custom logic here
    return 0.95

cfg = sa.AuditConfig(
    model_name="my_model",
    dataset_path="data.json",
    metrics=["custom_relevance"]
)

    Error Handling¶

    AuditRunner raises specific exceptions:

    • ConfigError: Invalid configuration parameters.
    • ConnectionError: API endpoint unreachable.
    • DatasetError: Input file missing or malformed.

    Wrap execution in try-except blocks for robust integration.

    try:
    report = runner.run(cfg)
except sa.ConfigError as e:
    print(f"Config invalid: {e}")
except sa.ConnectionError as e:
    print(f"API unreachable: {e}")

    Best Practices¶

    • Determinism: Set temperature=0.0 for reproducible results.
    • Batching: Use concurrency parameter for API calls. Monitor rate limits.
    • Data Quality: Validate dataset before execution. Malformed inputs cause DatasetError.
    • Logging: Enable debug logs for detailed trace. logging.getLogger("simpleaudit").setLevel(logging.DEBUG).

    Limitations¶

    • Local model inference requires compatible hardware (GPU recommended).
    • API audits depend on external service availability.
    • Custom metrics must be thread-safe if concurrency > 1.
