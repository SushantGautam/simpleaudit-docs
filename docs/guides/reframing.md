## Reframing & Prompt Engineering

The `simpleaudit` library provides a robust framework for evaluating the consistency and robustness of Large Language Models (LLMs). A critical component of this evaluation is **Reframing**, a technique that involves generating semantically equivalent but structurally distinct variations of a prompt. By testing how a model responds to these variations, developers can identify potential biases, instruction-following gaps, or instability in model outputs.

This module focuses on the generation and management of prompt reframes. It does not execute the LLM calls itself but provides the infrastructure to create, store, and manage the specific prompt variations required for a comprehensive audit.

### Core Concepts

In the context of `simpleaudit`, a **Reframe** is a specific instance of a prompt that has been modified to test a particular dimension of model behavior. Common reframing strategies include:

1.  **Paraphrasing**: Changing the wording while maintaining the exact semantic meaning.
2.  **Perspective Shifting**: Asking the same question from the perspective of a different persona (e.g., "As a security expert...").
3.  **Negative Constraints**: Explicitly stating what the model should *not* do.
4.  **Contextual Padding**: Adding irrelevant context to test if the model gets distracted.

The library abstracts the generation of these reframes, allowing developers to define a base prompt and a set of reframing strategies, then automatically generate the necessary test cases.

### Key Classes

#### `ReframeGenerator`

The `ReframeGenerator` class is the primary interface for creating prompt variations. It takes a base prompt and a list of reframing strategies, producing a list of `Reframe` objects.

**Parameters:**

*   `base_prompt` (str): The original prompt to be reframed.
*   `strategies` (list[str]): A list of strategy identifiers. Valid strategies include:
    *   `"paraphrase"`: Uses an LLM to generate a semantically equivalent prompt.
    *   `"persona"`: Prepend a persona context to the prompt.
    *   `"negative"`: Invert the instruction (e.g., "Do not explain" vs "Explain").
    *   `"padding"`: Add random filler text to the prompt.
*   `llm_client` (optional, BaseLLMClient): An optional LLM client instance used for strategies that require generative capabilities (like `"paraphrase"`). If not provided, the library will attempt to use a default client or raise an error for generative strategies.

**Methods:**

*   `generate()` (list[Reframe]): Generates the list of reframed prompts based on the configured strategies.
*   `get_strategy_names()` (list[str]): Returns the list of currently configured strategy names.

#### `Reframe`

The `Reframe` class represents a single reframed prompt instance. It is a data class that holds the prompt text and metadata about how it was generated.

**Attributes:**

*   `prompt` (str): The actual text of the reframed prompt.
*   `strategy` (str): The name of the strategy used to generate this reframe (e.g., `"paraphrase"`, `"persona"`).
*   `base_prompt` (str): The original prompt from which this reframe was derived.
*   `metadata` (dict): A dictionary containing additional context, such as the specific persona used or the random seed for padding.

### Usage Examples

#### Basic Reframe Generation

To generate reframes for a simple prompt, you can use the `ReframeGenerator` with non-generative strategies that do not require an external LLM call for the reframing process itself.

```python
from simpleaudit.reframing import ReframeGenerator

# Define the base prompt
base_prompt = "Explain the difference between TCP and UDP."

# Initialize the generator with specific strategies
# Note: 'persona' and 'padding' do not require an LLM client for generation
generator = ReframeGenerator(
    base_prompt=base_prompt,
    strategies=["persona", "padding"]
)

# Generate the reframes
reframes = generator.generate()

# Iterate through the results
for reframe in reframes:
    print(f"Strategy: {reframe.strategy}")
    print(f"Prompt: {reframe.prompt[:50]}...")
    print("-" * 40)
```

#### Using Generative Strategies (Paraphrasing)

Strategies like `"paraphrase"` require an LLM to generate the new prompt. You must provide an `llm_client` instance.

```python
from simpleaudit.reframing import ReframeGenerator
from simpleaudit.llm import OpenAIClient  # Example client, replace with your actual client

# Initialize an LLM client
llm_client = OpenAIClient(model="gpt-4")

# Initialize the generator with a generative strategy
generator = ReframeGenerator(
    base_prompt="What is the capital of France?",
    strategies=["paraphrase", "negative"],
    llm_client=llm_client
)

# Generate reframes
reframes = generator.generate()

# The 'paraphrase' reframe will have a prompt generated by the LLM
for reframe in reframes:
    if reframe.strategy == "paraphrase":
        print(f"Paraphrased Prompt: {reframe.prompt}")
    elif reframe.strategy == "negative":
        print(f"Negative Prompt: {reframe.prompt}")
```

### Configuration and Strategies

The behavior of the `ReframeGenerator` is determined by the `strategies` parameter. Below is a detailed breakdown of the supported strategies:

| Strategy Name | Description | Requires LLM Client? | Use Case |
| :--- | :--- | :---: | :--- |
| `paraphrase` | Generates a semantically equivalent prompt using an LLM. | Yes | Tests if the model is sensitive to specific wording. |
| `persona` | Prepends a role/persona to the prompt (e.g., "Act as a doctor..."). | No | Tests if the model's output changes based on assumed authority or context. |
| `negative` | Inverts the instruction (e.g., "Do not explain" vs "Explain"). | No | Tests instruction-following robustness and negation handling. |
| `padding` | Adds random, irrelevant text to the beginning or end of the prompt. | No | Tests if the model is distracted by irrelevant context. |

#### Customizing Persona Strategies

When using the `"persona"` strategy, you can specify which personas to use by passing a dictionary to the `metadata` of the generator or by using the `persona_config` parameter if available in your version. By default, a small set of common personas (e.g., "expert", "beginner", "skeptic") is used.

```python
# Example: Customizing persona (if supported by your version's API)
# Note: Check specific version docs for 'persona_config' parameter
generator = ReframeGenerator(
    base_prompt="Is this code secure?",
    strategies=["persona"],
    # persona_config={"personas": ["security_expert", "junior_dev"]}
)
```

### Best Practices

1.  **Combine Strategies**: For a comprehensive audit, it is recommended to use a combination of strategies. For example, using both `"paraphrase"` and `"persona"` can reveal if a model is both wording-sensitive and context-sensitive.
2.  **Control Randomness**: When using `"padding"`, ensure that the random seed is set if you need reproducible test cases. The `Reframe` object's `metadata` dictionary may contain the seed used.
3.  **Validate Reframes**: Before running a full audit, print the generated reframes to ensure they are valid and make sense. LLM-generated paraphrases can occasionally introduce errors.
4.  **Separate Generation from Execution**: The `ReframeGenerator` only creates the prompts. You must still pass these prompts to your LLM evaluation pipeline to get the actual responses. The `simpleaudit` library typically provides a separate `Evaluator` class to handle this execution phase.

### Integration with the Audit Pipeline

The reframes generated by `ReframeGenerator` are designed to be consumed by the `simpleaudit` evaluation engine. A typical workflow looks like this:

1.  **Define Base Prompt**: Create the original prompt you want to test.
2.  **Generate Reframes**: Use `ReframeGenerator` to create variations.
3.  **Execute Evaluations**: Pass the list of `Reframe` objects to the evaluator, which will send each prompt to the target LLM.
4.  **Analyze Consistency**: Compare the responses from the base prompt and the reframes to calculate a consistency score.

By leveraging the `Reframing & Prompt Engineering` module, developers can systematically probe the boundaries of their LLM applications, ensuring that models behave consistently across different phrasings and contexts. This is crucial for building reliable AI-powered features in production environments.
