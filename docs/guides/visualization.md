## Visualization

The `simpleaudit.visualization` module provides a built-in web server for serving and visualizing audit results. It uses **FastAPI** and **Uvicorn** to expose an interactive interface where developers can browse, filter, and inspect the JSON outputs generated by SimpleAudit runs.

This module supports two primary modes of operation:
1.  **Live Server**: A local web server that dynamically scans a results directory and serves the file tree and JSON data via API endpoints.
2.  **Standalone Export**: A utility to generate a self-contained HTML file with audit data inlined, suitable for sharing without running a server.

### Configuration

The visualization server behavior is controlled by environment variables:

| Variable | Description | Default |
| :--- | :--- | :--- |
| `SIMPLEAUDIT_VISUALIZER_SECRET` | If set, enables authentication. Requests must include this value in the `X-Secret` header. | `""` (Disabled) |
| `SIMPLEAUDIT_VISUALIZER_EMAIL` | Contact email displayed in the frontend when authentication is enabled. | `"sushant@simula.no"` |

### Starting the Server

To start the visualization server, use the `simpleaudit.visualization.server` module. The server requires a results directory to be configured.

```python
import uvicorn
from simpleaudit.visualization.server import app, RESULTS_DIR

# Set the path to your audit results directory
RESULTS_DIR = "/path/to/your/results"

# Start the server
uvicorn.run(app, host="127.0.0.1", port=8000)
```

Once running, navigate to `http://127.0.0.1:8000` in your browser. The root endpoint serves the main visualization interface (`visualizer.html`).

### API Endpoints

The server exposes several REST API endpoints for interacting with audit data.

#### `GET /api/auth`
Verifies the authentication status and provides configuration details.

*   **Response**:
    ```json
    {
      "ok": true,
      "enabled": false,
      "contact_email": "sushant@simula.no"
    }
    ```
    *   `enabled`: `true` if `SIMPLEAUDIT_VISUALIZER_SECRET` is set.
    *   `contact_email`: The value of `SIMPLEAUDIT_VISUALIZER_EMAIL`.

#### `GET /api/files`
Returns the file tree structure of the results directory. This endpoint is protected by the secret if authentication is enabled.

*   **Response**:
    ```json
    {
      "tree": [
        {
          "name": "experiment_1",
          "type": "folder",
          "path": "experiment_1",
          "children": [
            {
              "name": "results.json",
              "type": "file",
              "path": "experiment_1/results.json"
            }
          ]
        }
      ]
    }
    ```
    The tree includes folders, standard result files, and experiment files. Experiment files are identified by the presence of a `runs` dictionary in the JSON structure.

#### `GET /api/json/{file_path}`
Retrieves the contents of a specific JSON file from the results directory.

*   **Path Parameter**:
    *   `file_path`: The relative path to the JSON file within the results directory.
*   **Security**:
    *   Prevents directory traversal attacks by resolving the real path and ensuring it starts with the results directory root.
    *   Only serves files with a `.json` extension.
*   **Response**:
    *   `200 OK`: The JSON content of the file.
    *   `400 Bad Request`: If the path is invalid or the file is not a JSON file.
    *   `403 Forbidden`: If the path attempts to escape the results directory.
    *   `404 Not Found`: If the file does not exist.

### Data Validation

The module includes internal logic to validate the structure of audit results. A file is considered valid if it matches one of the following shapes:

1.  **Legacy Shape**: A list of audit result objects.
    ```json
    [
      {
        "scenario_name": "test_scenario",
        "severity": "high",
        "description": "..."
      }
    ]
    ```
2.  **Current Shape**: A dictionary with a `results` key containing a list of audit result objects.
    ```json
    {
      "results": [
        {
          "scenario_name": "test_scenario",
          "severity": "high",
          "description": "..."
        }
      ]
    }
    ```
3.  **Experiment Shape**: A dictionary with a `runs` key, where each value is a model label mapping to a list of run results.
    ```json
    {
      "runs": {
        "model_a": [
          {
            "results": [
              {
                "scenario_name": "test_scenario",
                "severity": "high",
                "description": "..."
              }
            ]
          }
        ]
      }
    }
    ```

The function `is_valid_audit_data(data)` can be used programmatically to check if a parsed JSON object conforms to these structures.

### Standalone HTML Export

For sharing audit results without requiring a running server, you can export a self-contained HTML file. This file includes the audit data inlined within the HTML, allowing it to be opened directly in a browser.

```python
from simpleaudit.visualization.server import export_standalone_html

# Export a single results file
export_standalone_html(
    json_path="/path/to/results.json",
    output_path="/path/to/standalone_report.html"
)
```

**Function Signature**:
`export_standalone_html(json_path: str, output_path: str) -> str`

*   **Parameters**:
    *   `json_path`: Path to the audit results JSON file.
    *   `output_path`: Where to write the standalone HTML file.
*   **Returns**:
    *   The output path.
*   **Raises**:
    *   `ValueError`: If the JSON is not valid audit data or if the template is missing.

The exported HTML file will automatically detect the inlined data and render it using the same visualizer interface as the live server.

### Authentication

If `SIMPLEAUDIT_VISUALIZER_SECRET` is set, all API endpoints (except `/api/auth`) require an `X-Secret` header with the correct value. The frontend will prompt for this secret if authentication is enabled.

Example request with authentication:
```bash
curl -H "X-Secret: your-secret-here" http://127.0.0.1:8000/api/files
```

### Troubleshooting

*   **500 Error: Results directory not set**: Ensure that `RESULTS_DIR` is set in the server module before starting the server.
*   **403 Forbidden**: This usually indicates a path traversal attempt or a misconfigured results directory. Verify that the file path is relative to the results directory.
*   **Empty File Tree**: Ensure that the results directory contains valid JSON files that match the expected audit result structures.
