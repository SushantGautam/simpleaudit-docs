## Reframing and Data Processing

The `simpleaudit` library provides robust utilities for transforming raw audit logs into structured, analyzable datasets. This module focuses on two critical aspects of the data pipeline: **Reframing**, which normalizes prompt structures for consistent comparison, and **Data Processing**, which cleans, filters, and aggregates audit records for statistical analysis.

### Overview

In automated auditing workflows, raw data often contains inconsistencies in prompt formatting, variable placeholders, or metadata structures. The `simpleaudit` data processing subsystem addresses these issues by providing a set of deterministic transformation functions. These tools ensure that downstream analysis, such as drift detection or performance benchmarking, operates on a uniform data schema.

The core functionality is encapsulated in the `simpleaudit.processing` module. Developers interact with this module primarily through the `AuditProcessor` class and a suite of utility functions for string manipulation and data normalization.

### Core Classes

#### `AuditProcessor`

The `AuditProcessor` is the primary interface for handling audit data streams. It encapsulates the logic for parsing raw log entries and applying reframing rules.

**Constructor:**

```python
from simpleaudit.processing import AuditProcessor

def __init__(self, config: dict = None, strict_mode: bool = False):
    """
    Initialize the AuditProcessor.

    Args:
        config: A dictionary containing processing rules.
                Supported keys:
                - 'placeholder_pattern': Regex pattern for identifying variables (default: r'\{[^}]+\}')
                - 'max_length': Maximum allowed length for prompt strings (default: 10000)
                - 'encoding': Character encoding for file I/O (default: 'utf-8')
        strict_mode: If True, raises an exception on malformed data.
                     If False, logs a warning and skips the record.
    """
```

**Key Methods:**

| Method | Description |
| :--- | :--- |
| `process_record(record: dict) -> dict` | Processes a single audit record, applying reframing and cleaning rules. Returns the processed dictionary. |
| `process_batch(records: list[dict]) -> list[dict]` | Processes a list of audit records. Efficiently handles large batches using vectorized operations where possible. |
| `validate_schema(record: dict) -> bool` | Validates that a record contains all required fields (`prompt`, `response`, `timestamp`, `model_id`). |

### Reframing Techniques

Reframing is the process of standardizing prompts to remove dynamic variables while preserving the semantic structure. This is essential for grouping similar prompts together for analysis.

#### `reframe_prompt`

This utility function applies a series of transformations to a prompt string to create a "canonical" form.

```python
from simpleaudit.processing.utils import reframe_prompt

def reframe_prompt(prompt: str, placeholder_pattern: str = r'\{[^}]+\}') -> str:
    """
    Reframes a prompt by replacing dynamic placeholders with a standard token.

    Args:
        prompt: The raw prompt string.
        placeholder_pattern: A regular expression pattern to match placeholders.
                             Default matches {variable} style placeholders.

    Returns:
        A string where all matched placeholders are replaced with '<VAR>'.
    """
```

**Example Usage:**

```python
raw_prompt = "Hello {name}, your order {order_id} is ready."
reframed = reframe_prompt(raw_prompt)
# Output: "Hello <VAR>, your order <VAR> is ready."
```

This normalization allows `simpleaudit` to group "Hello {name}..." and "Hello {user}..." as the same logical prompt template.

### Complete Workflow Example

The following example demonstrates a complete data processing pipeline using `simpleaudit`. It reads raw logs, reframes prompts, filters for a specific model, and generates summary metrics.

```python
import json
from simpleaudit.processing import AuditProcessor
from simpleaudit.processing.aggregation import aggregate_metrics

# 1. Initialize the processor with custom configuration
processor = AuditProcessor(
    config={
        'placeholder_pattern': r'\{[^}]+\}',
        'max_length': 5000
    },
    strict_mode=False
)

# 2. Simulate raw audit data
raw_logs = [
    {
        "prompt": "Summarize this text: {text}",
        "response": "Here is the summary...",
        "model_id": "gpt-4",
        "timestamp": "2023-10-27T10:00:00Z",
        "status": "success"
    },
    {
        "prompt": "Summarize this text: {article}",
        "response": "Summary provided.",
        "model_id": "gpt-4",
        "timestamp": "2023-10-27T10:01:00Z",
        "status": "success"
    },
    {
        "prompt": "Translate to French: {phrase}",
        "response": "Traduction...",
        "model_id": "claude-3",
        "timestamp": "2023-10-27T10:02:00Z",
        "status": "error"
    }
]

# 3. Process the batch
processed_logs = processor.process_batch(raw_logs)

# 4. Filter for a specific model
gpt4_logs = [log for log in processed_logs if log['model_id'] == 'gpt-4']

# 5. Aggregate metrics
metrics = aggregate_metrics(gpt4_logs)

print(f"Total GPT-4 Requests: {metrics['count']}")
print(f"Unique Prompt Templates: {metrics['unique_prompts']}")
print(f"Error Rate: {metrics['error_rate']}%")
```

**Output:**
```
Total GPT-4 Requests: 2
Unique Prompt Templates: 1
Error Rate: 0.0%
```

Note that even though the raw prompts used different variable names (`{text}` vs `{article}`), the reframing process normalized them to the same template, resulting in `unique_prompts` being 1.

### Configuration Options

The `AuditProcessor` accepts a `config` dictionary to customize its behavior. The following options are supported:

| Key | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `placeholder_pattern` | `str` | `r'\{[^}]+\}'` | Regex pattern for identifying dynamic variables in prompts. |
| `max_length` | `int` | `10000` | Maximum character length for prompt and response fields. Records exceeding this are truncated or flagged depending on `strict_mode`. |
| `encoding` | `str` | `'utf-8'` | Character encoding used when reading or writing data files. |
| `timestamp_format` | `str` | `'%Y-%m-%dT%H:%M:%SZ'` | Expected format for timestamp fields. Used for validation and sorting. |

### Error Handling

When `strict_mode` is set to `True` (default), the `AuditProcessor` will raise a `DataValidationError` if a record is missing required fields or if the timestamp format is invalid. This is recommended for production pipelines where data integrity is critical.

When `strict_mode` is `False`, the processor will log a warning to the `simpleaudit.processing` logger and skip the malformed record. This is useful for exploratory analysis where partial data is acceptable.

### Best Practices

1.  **Consistent Placeholder Patterns**: Ensure that your `placeholder_pattern` regex matches the specific variable syntax used in your application (e.g., `{var}`, `{{var}}`, or `$var`).
2.  **Batch Processing**: For large datasets, always use `process_batch` instead of looping through `process_record`. The batch method optimizes memory usage and processing speed.
3.  **Pre-Validation**: If your data source is unreliable, consider running `validate_schema` on individual records before adding them to a batch to identify problematic entries early.

By leveraging these reframing and data processing tools, developers can ensure that their audit data is clean, consistent, and ready for advanced analysis within the `simpleaudit` ecosystem.
